## 이번 주를 관통한 흐름

**1. "보기 좋다"와 "시킨 걸 했다"가 같은 지표처럼 보이지만 실제로는 갈라지는 축이라는 걸, 네 분야가 서로 다른 방식으로 증명했다.** [[2610.28402|StreamEval]]이 가장 직접적인 증거다. 37개 실시간 영상 생성 모델을 평가했더니 Quality·Identity 같은 외형 지표는 높은데 Following·Edit Success 같은 "요청을 실제로 실행했는가" 지표는 전 영역에서 낮았고, 레퍼런스 편집 과제 최고 Edit Success는 100점 만점에 15점에 그쳤다. Quality 1위 모델이 Following·Continuity에서는 최하위권이었다는 사례는 두 축이 단순히 상관관계가 약한 정도가 아니라 거의 무관하다는 걸 보여준다. [[2610.26203|FocusGUI]]는 같은 균열을 GUI 에이전트에서 발견한다. 화면을 잘라내 집중시키는 기존 refinement 기법들(OmniParser, RegionFocus, DRS-GUI)은 Task Match는 거의 그대로 두면서 Exact Match·진행률은 오히려 28~35% 악화시켰는데, 저자는 이걸 "공간적으로 좁히는 과정에서 좌표·텍스트 근거까지 함께 잘려나간다"고 설명한다. 화면이 더 깨끗해 보이는 것과 다음 행동의 인자(argument)를 정확히 맞히는 것이 별개라는 뜻이다. [[2610.31329|WeVisOne-VL]]도 같은 패턴을 보여주는데, referring segmentation의 cIoU는 다른 전용 모델과 비슷한 수준인 반면 "대상이 없을 때 거절하는" rejection rate에서만 압도적으로 앞섰다(Ref-ZOM 86.0% vs 기존 모델 0.3~41.9%) — 마스크를 그럴듯하게 그리는 능력과 "이건 애초에 없는 대상"이라고 정직하게 판단하는 능력이 따로 논다는 의미다. [[2610.24738|LayerEditor]]는 이 균열을 수치로 가장 깔끔하게 포착하는데, 바로 생성한 캔버스(Direct) 품질에서는 경쟁 모델에 밀리는 경우가 있지만 레이어로 쪼갠 뒤 다시 합성한 결과(Composite)에서는 전부 1위를 차지한다. Seedream5-Pro는 Direct에서 Composite로 갈 때 SSIM이 11.6% 떨어지는데 LayerEditor는 1.0%만 떨어진다 — "한 장 그림을 잘 그리는 능력"과 "그 그림을 레이어로 쪼개도 품질이 새지 않는 능력"이 다른 능력이라는 걸 직접 증명한 셈이다. 네 논문을 나란히 두면, 서로 무관해 보이는 분야에서 같은 질문 — "지금 쓰는 지표가 겉모습을 재는지 실행력을 재는지" — 이 거의 동시에 제기되고 있다는 게 보인다.

**2. 새 모듈을 얹는 대신 모델이 이미 갖고 있는 표현을 재활용하는 설계가 반복해서 등장했다.** [[2610.22276|MJev-Spatial]]은 공간 질문에 답하려고 새 분류 헤드를 학습시키는 대신, 백본 마지막 full-attention 레이어의 사전학습된 $W_Q$, $W_K$를 그대로 candidate scoring에 재사용한다. 추가 학습 파라미터 없이 기반 모델 대비 5.6배 빠른 추론을 얻는다. [[2610.31329|WeVisOne-VL]]은 비슷한 발상을 픽셀 레벨로 확장하는데, segmentation을 위해 별도 모델(SAM 등)을 붙이는 대신 VLM이 이미 생성한 `<OBJ>` 토큰의 hidden state와 직전 예측 박스를 그대로 디코더 쿼리로 재사용한다($q_i=W_h h_i$). 둘 다 "이미지를 다시 들여다보거나 새 표현을 학습할 필요 없이, 모델이 방금 만든 걸 그대로 다음 단계의 질의로 쓴다"는 같은 절약을 하고 있다. [[2610.24738|LayerEditor]]는 같은 절약을 모델이 아니라 학습 과정에 적용한 경우로 읽을 수 있다 — 레이어 출력으로 확장하면서 떨어지는 편집 품질을 새로운 정규화 항이나 데이터로 메우는 대신, 사전학습된 편집 모델 자체를 frozen teacher로 다시 불러와 student가 지나가는 바로 그 지점에서 비교한다(C-EPD). 세 논문 모두 "새 능력을 붙이려면 새 모듈이나 새 학습 신호가 필요하다"는 기본 가정을 피해서, 모델이나 파이프라인이 이미 갖고 있는 것(attention 가중치, 토큰 하나, 과거의 자기 자신)을 다른 용도로 재활용하는 쪽을 택했다. [[2610.26203|FocusGUI]]의 설계도 이 계열에 가깝다 — 백본과 원본 임베딩 경로는 건드리지 않고, action 직전 K개 위치에 zero-init 잔차를 "덧셈"으로만 주입한다(치환이 아니라). 저자들이 부록에서 증명하듯 이 잔차가 매 스텝 새로 계산되어 상태를 들고 다니지 않는다는 점도 MJev-Spatial·WeVisOne-VL의 "그때그때 재계산" 기조와 통한다.

**3. 자기 벤치마크로 자기를 검증하는 순환 구조가, 이번 주 거의 모든 논문에서 리뷰어의 의문으로 남았다.** [[2610.24738|LayerEditor]]의 QIL-Decomp-FT·QIL-Edit-SFT는 LayerEditor-100K로 직접 fine-tuning된 반면 Seedream5-Pro는 API zero-shot으로만 비교되고, 벤치마크 자체도 학습 데이터와 같은 소스(Crello, ScaleEdit)에서 파생됐다. [[2610.31329|WeVisOne-VL]]의 rejection 비교 벤치마크(WeRef-Bench, WeRefMat, PR-Bench)는 전부 저자가 직접 만든 것이고, 비교 대상 모델들은 애초에 rejection을 학습한 적이 없다. [[2610.26203|FocusGUI]]가 비교하는 화면 refinement 베이스라인들도 omni-modal 멀티스텝 세팅을 겨냥해 설계된 게 아니다. [[2610.28402|StreamEval]]은 한 걸음 더 나아가 채점 자체가 Qwen 계열 VLM judge에 의존하는데 judge 모델 계열 간 편향 검증이 없고, 사람 평가와의 상관관계도 아직 공개되지 않았다. 네 편 모두 저자들이 이런 한계를 어느 정도 투명하게 밝히고 있다는 공통점은 있지만, "자체 데이터·자체 벤치마크·자체 모델이 채점"하는 구조가 이렇게 한 주에 몰려 나온다는 건, 레이어드 편집이든 GUI grounding이든 omni-modal rejection이든, 아직 공인된 제3자 벤치마크가 성숙하지 않은 영역일수록 이 순환 구조를 피하기 어렵다는 뜻으로 읽힌다.

이번 주 나머지 두 편은 위 흐름과는 결이 다르다. [[2610.23479|HexaShell]]은 로봇 코딩 에이전트가 실패하면 같은 모델이 로그·코드만 보고(이미지는 거의 안 보고) "도구"를 고쳐 다음 에피소드에 재사용하게 하는데, 성공 여부가 "추론"이 아니라 "접촉이 필요한 정도"를 따라간다는 지도화가 핵심이었다. [[2610.26802|BrainLoRA]]는 완전히 다른 도메인(뇌 반응 예측)에서 causal masking을 이용한 single-pass 추출로 feature-extraction 비용을 350배 줄여, 지금까지 계산량 때문에 얼린 채로만 쓰던 거대 멀티모달 backbone에 LoRA 적응을 전부 적용할 수 있게 만들었다. 둘 다 "크고 비싼 모델을 다시 학습시키지 않고 바깥에서 효율적으로 다룬다"는 점에서는 흐름 2와 약하게 공명하지만, 독립된 주제로 보는 게 맞다.

## 다음 주 주목할 것

StreamEval·FocusGUI·WeVisOne-VL·LayerEditor가 네 분야에서 동시에 드러낸 "품질과 실행의 분리"가 다음 주에도 반복되는 패턴인지, 아니면 이번 주 우연히 겹친 것인지 지켜볼 만하다. 특히 이 네 편 모두 "실행했는가"를 재는 지표(Following/Edit Success, Rejection rate, Composite 재구성)를 새로 설계하거나 강조했다는 공통점이 있는데, 다음 벤치마크 논문들이 이 "실행 축"을 기본 축으로 채택하기 시작하는지가 관전 포인트다. 또한 MJev-Spatial·WeVisOne-VL·LayerEditor가 보여준 "기존 표현 재활용" 설계가 품질-실행 분리 문제에 대한 해법으로도 이어질 수 있을지 — 예를 들어 frozen teacher나 재사용된 토큰이 "그럴듯해 보이지만 틀린" 출력을 걸러내는 역할까지 할 수 있을지 — 가 다음에 읽을 논문들에서 확인하고 싶은 지점이다.
