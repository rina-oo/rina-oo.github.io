## 이번 주를 관통한 흐름

**1. 월드 모델을 세 개의 다른 층위에서 건드린 한 주.** [[2608.25518|게임 엔진 트랙터리 엔진]]은 월드 모델을 "무엇으로 학습시킬 것인가"의 문제로 보고, 게임 엔진의 조밀한 구조적 체크(충돌·물리·내비메시)와 사람의 희소한 최종 승인을 묶은 RLHEV라는 학습 신호를 제안한다. [[2608.15875|GigaBrain-0.7]]은 그렇게 학습된 월드 모델을 "어떻게 실제 로봇 정책 안에 배치할 것인가"의 문제로 다루는데, System 3(World Value Model)이 예측한 subgoal 이미지와 가치를 System 1(행동)에 조건으로 주입해 휴머노이드 복합 조작 성능을 크게 끌어올린다. 그리고 [[2608.27345|PAWBench]]는 정반대 방향에서 "그렇게 배치되거나 그렇게 만들어진 월드 모델이 애초에 맞기는 한가"를 묻는다 — 같은 조건을 반복했을 때 진짜 확률 분포를 재현하는지 검증한다. 세 논문을 나란히 놓으면 데이터 엔진 → 배치 아키텍처 → 정합성 평가로 이어지는 파이프라인 전체가 한 주 안에 다 등장한 셈이다. 특히 GigaBrain의 World Value Model이 딱 하나의 subgoal 이미지를 예측해 정책에 주입하는 방식은, PAWBench가 지적하는 "한 번의 그럴듯한 미래로는 부족하다"는 비판을 정면으로 맞는 지점이기도 하다. GigaBrain은 그 예측이 반복했을 때도 통계적으로 옳은지는 검증하지 않기 때문이다.

**2. 결과가 아니라 과정을 채점한다.** [[2608.23283|Apodex 1.1]]은 에이전트 지능을 최종 정답률이 아니라 "완료된 작업"으로 재정의하면서, HDS6라는 별도의 프로세스 평가 프레임워크로 실행 과정 자체를 채점한다. [[2608.26005|VoiceMem]]은 정보(좌뇌)와 감정·페르소나(우뇌)를 애초에 다른 자료구조로 분리해, 일시적 반응이 성향으로 잘못 귀속되는 문제를 구조적으로 막는다. [[2608.27345|PAWBench]] 역시 "영상 하나가 그럴듯한가"라는 결과 판정 대신 "반복했을 때의 분포가 맞는가"라는 과정 지향적 질문으로 무게중심을 옮긴다. 세 논문 모두 평가 방식 자체를 결과 중심에서 과정·구조 중심으로 옮기려는 시도라는 점에서 겹친다.

**3. 스케일링을 축 분해로 푸는 패턴.** [[2608.20061|μP 하이퍼파라미터 전이]]는 폭 스케일링(μP)과 토큰 스케일링(로그-로그 회귀)을 분리해 2차원 스윕을 1차원으로 줄인다. Apodex의 task contract도 워크스페이스·목표·행동·전이·검증기를 튜플로 분해해 환경 구성과 평가를 같은 언어로 기술하고, VoiceMem은 정보와 정서를 분리해 각각 다른 갱신 규칙을 적용한다. 세 논문 모두 "얽혀 있는 문제를 서로 독립적인 축으로 쪼개고 각 축을 따로 최적화한다"는 동일한 설계 철학을 프리트레이닝 인프라, 에이전트 오케스트레이션, 음성 메모리라는 전혀 다른 응용에 각각 적용한 셈이다.

## 다음 주 주목할 것

RLHEV류의 "엔진 검증 + 사람 승인" 학습 신호가 실제 로봇 데이터(sim-to-real)로 넘어가는 후속 실험이 나올지, 그리고 PAWBench 같은 분포 정합성 평가가 GigaBrain류의 배치형 월드 모델에도 적용되어 "그 예측이 통계적으로 옳은가"까지 검증하는 논문이 등장할지 지켜볼 만하다.
