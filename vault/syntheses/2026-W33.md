이번 주(8/10~8/16)는 세 편 모두 "무엇을 평가 지표로 삼을 것인가"라는 질문에서 만난다. 셋 다 표면적으로는 서로 다른 분야(에이전트 패러다임, red-teaming, LLM 라우팅)를 다루지만, 공통적으로 "단일 스칼라 지표가 실제로 중요한 것을 가린다"는 문제의식에서 출발해 각자의 다차원 평가 장치를 제안한다.

## 흐름 — 단일 점수 하나로는 안 보이는 것

[[2608.10915|ComBodied Agents]]는 task 성공률이라는 단일 지표가 사용자의 이해도·자율성·역량 저하 같은 "부작용"을 완전히 놓친다고 지적하며, agency preservation이라는 8개 non-compensatory(가중합으로 뭉개지지 않는) 지표를 대안으로 제안한다. [[2608.06867|LLMRouter]]는 비슷한 문제를 라우팅 영역에서 실증한다 — quality-only 설정에서 1위였던 라우터가 비용 가중치 β를 조금만 올려도 순위가 크게 뒤집히는 걸 직접 보여주면서, "품질 하나로 줄 세운 순위표"가 애초에 신뢰할 수 없는 지표라는 걸 데이터로 증명한다. 두 논문 모두 결론은 같다: 여러 축을 하나의 점수로 뭉개지 말고 각 축을 따로 보고해야 한다는 것.

[[2608.00677|OpenART]]는 이 흐름에 시간축이라는 세 번째 차원을 더한다. 저자들은 기존 red-teaming 벤치마크가 "프롬프트 인젝션 직후 도구 호출"만 감시하는 좁은 창을 쓴다고 비판하면서, 실제 안전 실패는 오염된 상태를 읽은 시점으로부터 median 37 액션, 무려 41%p 지연된 뒤에야 발현된다는 long-horizon safety drift를 정량적으로 보여준다. 이건 "그 순간의 점수"가 아니라 "충분히 긴 시간에 걸쳐 관찰해야만 보이는 실패"라는 점에서, ComBodied Agents가 강조하는 longitudinality(장기 관찰이 필요한 capability growth·over-reliance 같은 속성)와 정확히 같은 구조의 주장이다. 둘 다 "지금 당장 잘 작동하는 것처럼 보인다"는 것과 "실제로 안전하거나 사용자에게 이롭다"는 것 사이에는 시간이 벌려놓는 간극이 있다고 말한다.

## 논문 간 연결점

세 논문을 나란히 놓으면 "평가 지표 설계 자체가 연구 대상이 되어야 한다"는 하나의 메타 주장으로 수렴한다. ComBodied Agents는 지표를 아예 새로 만들자(agency preservation)는 규범적 제안이고, OpenART는 기존 지표(ASR)를 유지하되 측정 시점을 넓혀야 한다(long-horizon)는 실증이고, LLMRouter는 기존 지표(quality)를 신뢰하지 말고 다축으로 쪼개 인프라 차원에서 비교하자는 제안이다. 방향은 다르지만 셋 다 "성공/실패를 가르는 하나의 숫자"에 대한 불신에서 출발한다는 점이 흥미롭다. 또 하나 겹치는 지점은 세 논문 모두 자신들이 제안하는 새 지표나 벤치마크의 한계를 스스로 인정한다는 점이다 — ComBodied는 agency 지표의 실제 측정 방법론이 없다는 걸, OpenART는 judge 모델(GLM-5.2)이 자기 자신을 평가 대상에 포함시킨 잠재적 편향을, LLMRouter는 컴포넌트 공식화를 직접 검증하는 ablation이 없다는 걸 각각 밝힌다.

## 다음 주 주목할 것

OpenART의 long-horizon drift 측정 방법론(propagation distance)이 ComBodied Agents가 요구하는 capability-growth/over-reliance 측정에 그대로 응용될 수 있을지, 그리고 LLMRouter 같은 다축 비교 인프라가 agency preservation처럼 "성공률 이외의 지표"를 요구하는 다른 에이전트 평가 영역으로 확장되는지 지켜볼 만하다.
