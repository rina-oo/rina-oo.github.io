# 누가 누구에게 무슨 말을 했나 — SpeakerMem-R1: Speaker-Centered Dual-Track Memory for Multi-Party Dialogue

> 원제: 누가 누구에게 무슨 말을 했나 — SpeakerMem-R1: Speaker-Centered Dual-Track Memory for Multi-Party Dialogue
> 리뷰: [블로그 전문](https://rina-oo.github.io/posts/2609.26780/)

## TL;DR
다자(multi-party) 대화 메모리에서 기존 시스템이 놓치는 지점은 "누가 말했고 그 내용이 누구에 관한 것인가(source-owner)"의 귀속 정보다. SpeakerMem-R1은 원문 메시지를 그대로 보존하는 System 1과 인물/그룹 단위로 가공한 4개 파생 레이어(System 2)를 분리 저장하고, 질의 시점에 Anchor-Separate-Resolve-Compose로 재조합한다. 이 파생 레이어를 쓰는 Writer를 SpeakerLevenshtein(owner 버킷별 매칭 + worst-owner 페널티) 보상과 speaker-conditioned GRPO로 학습시켜, Qwen2.5-3B가 DeepSeek-V4-Flash 대비 95.4%의 정확도에 도달한다. GroupMemBench/SocialMemBench/EverMemBench 세 벤치마크에서 SOTA, EverMemBench 공개 리더보드에서도 1위(62.33%).

## 핵심 기여
- 레코드를 `(x, src, own, scope, event, time, state, ref)` 구조체로 표현해 출처(source)와 소유자(owner)를 끝까지 분리 유지하는 설계. self-report는 src=own, 타인에 대한 관찰/전언은 src≠own.
- 이중 트랙 메모리: System 1(verbatim, append-only, from_ids로 provenance 제공) + System 2(4레이어: Person Core/Profile, Group Interaction/Insight). UPDATE는 덮어쓰지 않고 links/superseded_by로 체인 연결.
- 질의 시 두 트랙을 독립 예산으로 검색 후 결합(Anchor-Separate-Resolve-Compose). 파생 레이어가 비면 해당 인물의 원문으로 fallback.
- SpeakerLevenshtein: owner 버킷 내 Hungarian 1:1 매칭 기반 soft F1의 macro-average(w=0.80) + worst-owner(w=0.20) 결합. 빈도 높은 화자가 저빈도 화자/GROUP 오류를 가리는 것을 방지.
- Terminal QA gain(System1+2 vs System1-only의 정답률 차)을 감쇠(γ=0.95)로 역전파해 writing position별 보상에 결합, speaker-conditioned GRPO로 Writer만 업데이트(검색기·답변기는 고정).
- Qwen2.5-3B Writer가 SFT 대비 +10.82%p(57.38%→68.20%), LLM writer(DeepSeek-V4-Flash, 71.48%) 대비 격차 3.28%p까지 축소.

## 한계
- RL 학습 데이터가 15개 네트워크(대부분 SocialMemBench 출신)로 매우 작아, 성능 향상이 SocialMem 스타일 대화에 대한 국소 적합일 가능성을 배제하기 어려움. 다른 벤치마크 스타일로 직접 RL을 돌린 결과는 미보고.
- EverMemBench 리더보드에서 Multi-hop·Role(역할 귀속) 항목은 EverOS/RippleMem에 밀림 — 이 논문의 핵심 주장(source-owner 분리)과 가장 직결되는 Role 항목에서 오히려 약하다는 점에 대한 원인 분석이 부족.
- 질문당 평균 토큰 소비가 BM25/Embed 대비 7~20배(GroupMemBench 기준 약 27,000 vs 1,289). 비용-성능 트레이드오프 논의가 부록 원표 수준에 그침.
- Anchor-Separate-Resolve-Compose가 별도 실행 메커니즘이 아니라 기존 동작의 사후적 네이밍이라고 저자 스스로 명시 — 독립적 기여로 보기엔 애매함.
- LoCoMo(2인 대화) boundary test에서 Multi-hop(41.13%)·Open-domain(40.62%)이 LightRAG 대비 크게 낮음. 다자 대화 최적화 설계이므로 예상된 결과지만 범용성의 한계를 보여줌.
