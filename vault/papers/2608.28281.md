# 코딩 에이전트에게 '뭘 시킬지'만 판단하는 모델을 따로 평가한다면 — LoopArena: Benchmarking Models as Runtime Controllers for Loop Engineering

> 원제: 코딩 에이전트에게 '뭘 시킬지'만 판단하는 모델을 따로 평가한다면 — LoopArena: Benchmarking Models as Runtime Controllers for Loop Engineering
> 리뷰: [블로그 전문](https://rina-oo.github.io/posts/2608.28281/)

## TL;DR
코딩 에이전트(Worker)를 고정하고, 매 라운드 진행 상황을 요약한 Evidence Packet을 읽어 다음 지시(Loop Contract)를 내리거나 정지를 결정하는 별도 모델(Controller)의 능력만 분리 평가하는 벤치마크. 실행 비용이 다른 세 단계(Type I: 4지선다 Contract 선택, Type II: 부분 태스크, Type III: 전체 태스크)로 5개 모델(Qwen3.7-Plus, DeepSeek-V4-Flash-0731, GLM 5.2, GPT-5.5, Claude Opus 4.8)을 비교. 전체 태스크 최고 성공률(GPT-5.5)이 24.69%에 그쳐 장기 루프 제어의 어려움을 보여주고, Type II가 64.4% 낮은 비용으로 Type III와 유사한 순위(Spearman ρ=0.9747, Core 채점 기준)를 재현함을 확인.

## 핵심 기여
- Controller-Worker-Reporter 3-agent 분리 구조 제안: Worker는 코딩 도구를 독점 사용하고, Reporter는 읽기 전용 요약만 생성(대화는 비영속), Controller는 Evidence Packet만 보고 Loop Contract(advance/verify/stop)를 발행 — 코딩 능력과 루프 관리 능력을 실험적으로 분리
- SCBench·BeyondSWE 소스 태스크로부터 실행 비용이 다른 3단계(Type I/II/III) 벤치마크 구성. Type I은 벤치마크 구축 시점에 4개 후보 Contract를 두 개의 예측 등록된 시드로 replay하여 정답을 미리 고정, 평가 시점엔 Worker 실행 없이 4지선다로 채점
- Type II(부분 태스크)가 Type III(전체 태스크) 대비 평균 64.4% 낮은 추론 비용으로 유사한 Controller 순위(ρ=0.9747)를 재현함을 입증해, 저비용 대리 평가 지표로서의 타당성을 정량적으로 검증
- Fixed control(목표를 매번 그대로 반복 지시)이 Type II에서는 no-control보다 우세(39.51→46.91%)하지만 Type III에서는 no-control과 동일(18.52%)함을 발견 — 상태 적응형 가이드가 장기 태스크에서 필수적임을 시사
- Type I 문항이 표면적 지름길(다수결 위치, 후보 길이, 어휘 중복 등)로 풀리지 않음을 결정론적 베이스라인(최고 31.11%)로 검증해 문항 타당성 확보

## 한계
- 저자 인정 한계: 저장소 단위 코딩 태스크와 Controller-Worker 조직 구조에 한정. 다른 소프트웨어 도메인, Worker 계열, 다중 Worker 설정으로의 확장은 향후 과제
- 모든 Type II/III 결과가 단일 Worker(Qwen3.7-Plus)에 고정되어 있어, Controller 순위가 다른 Worker에서도 재현되는지는 검증되지 않음
- GLM 5.2는 비용 최저지만 성공률 최하위권인데, 평가의 절반 이상(Type II 54.76%, Type III 75.93%)에서 출력이 20,480토큰 한도에 도달한 프로토콜 실패가 섞여 있어 판단력 부족과 출력 절단으로 인한 실패가 분리되지 않음
- 핵심 실용 주장(Type II가 Type III의 저비용 대리 지표)을 뒷받침하는 상관계수(ρ=0.9747)가 SCBench 채점 기준에 매우 민감 — All checks 기준 0.1481, All non-error checks 기준 -0.2962로 부호까지 뒤집힘. 본문에서 강조한 채점 기준 하나만으로 일반화하기엔 근거가 약함
- 비용 산정이 프롬프트 캐싱을 가정하지 않아 실제 프로덕션 비용과 괴리가 있을 수 있음
