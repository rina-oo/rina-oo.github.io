# 편집하면서 동시에 레이어로 쪼갠다 — LayerEditor: Editing Images into Reusable Layers via Compositional Edit-Prior Distillation

> 원제: 편집하면서 동시에 레이어로 쪼갠다 — LayerEditor: Editing Images into Reusable Layers via Compositional Edit-Prior Distillation
> 리뷰: [블로그 전문](https://rina-oo.github.io/posts/2610.24738/)

## TL;DR
instruction 기반 이미지 편집 모델은 편집 결과를 하나의 평평한(flattened) 캔버스로만 내놓아 레이어 단위 재편집이 불가능하다는 문제를 겨냥한 논문. 편집 캔버스와 N개의 RGBA 레이어를 하나의 토큰 시퀀스로 동시에 denoise하고(In-Context RGB-Alpha Token Modeling), 레이어 확장 과정에서 떨어지는 편집 품질을 frozen teacher로 다시 끌어올리는 on-policy distillation(C-EPD)을 제안. 10만 쌍 규모 데이터셋 LayerEditor-100K와 두 벤치마크(Crello-Testset, ScaleEdit-Testset)를 자체 구축해 Composite SSIM/FID, Alpha IoU 전 항목 1위 달성.

## 핵심 기여
- In-Context RGB-Alpha Token Modeling: 편집 캔버스 $\mathcal D$와 레이어 스택 $\mathcal S=\{(R_i,A_i)\}$를 하나의 joint latent sequence로 묶어 동시에 denoise. layer-aware rotary coordinate $s$(소스=-1, 캔버스=0, 레이어 $i$의 RGB/Alpha=$2i+1$/$2i+2$)로 필드 구분. 레이어 개수가 가변이어도 구조 변경 없이 대응.
- 전용 Alpha 디코더: 사전학습 RGB VAE 디코더를 그대로 쓰지 않고 opacity 복원에 특화된 디코더를 별도 학습. 반투명 경계·미세 구조 복원에 기여(ablation에서 RGBA L1 0.0578→0.0350).
- C-EPD(Compositional Edit-Prior Distillation): frozen pretrained editor를 teacher로 두고, student의 denoising 궤적 위 중간 상태에서 (1) Direct velocity matching + (2) 예측 레이어를 alpha-compositing한 이미지와 teacher 디코딩 타겟 간 pixel loss, 두 항을 결합. 두 항 중 하나만 쓰면 한쪽 지표(edit consistency)는 오르지만 다른 쪽(visual quality, layer segmentation)이 떨어지는 trade-off가 있어 반드시 함께 써야 함.
- LayerEditor-100K: 네이티브 레이어 디자인(Crello, PrismLayersPro)에서 만드는 Route A와 평평한 편집 쌍(ScaleEdit)을 분해·검증해서 만드는 Route B, 두 경로로 10만 쌍 구축. 텍스트 48%/오브젝트 37%/포스터 전체 15% 편집, 레이어 2~10개.
- Composite 지표 기준 전 항목 1위. Direct→Composite 품질 손실이 경쟁 모델 대비 훨씬 작음(ScaleEdit에서 Seedream5-Pro Seq. 11.6% 하락 vs LayerEditor 1.0% 하락). 속도도 41.5s/sample로 경쟁 파이프라인(80~320s)보다 빠름(단, 하드웨어 미통제 비교).

## 한계
- rubric 기반 평가(edit consistency, layer segmentation 등 5개 지표)가 Gemini-3.1-Pro 단일 평가자에 전적으로 의존. 저자도 "VLM 점수를 사람 판단과 대조 검증하지 않았다"고 명시.
- 비교 대상 중 QIL-Decomp-FT, QIL-Edit-SFT는 LayerEditor-100K로 직접 fine-tuning된 반면 Seedream5-Pro는 API zero-shot 비교라 공정성이 혼재됨. 벤치마크 자체도 학습 데이터와 같은 소스(Crello, ScaleEdit)에서 파생.
- 텍스트가 여전히 래스터화된 픽셀로만 존재(편집 가능한 폰트/벡터 아님). 레이어 개수는 최대 10개까지만 학습·평가, 더 복잡한 디자인에서의 scalability 미검증.
- 코드·가중치 미공개(확인 시점 기준 GitHub 링크 없음), 직접 재현 불가.
