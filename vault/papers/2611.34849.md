# N×M 문제를 N+M으로 — Real2SimLab (코딩 에이전트용 Real-to-Sim 통합 평가 플랫폼)

> 원제: N×M 문제를 N+M으로 — Real2SimLab (코딩 에이전트용 Real-to-Sim 통합 평가 플랫폼)
> 리뷰: [블로그 전문](https://rina-oo.github.io/posts/2611.34849/)

## TL;DR
Real-to-simulation transfer(영상 → 물리 시뮬레이션 복원) 분야에서 코딩 에이전트가 시뮬레이션 프로그램을 직접 작성하는 새 패러다임이 등장했으나, 6개 벤치마크(Physics-IQ, Video2World, 4DCodeBench, PhysCodeGym, PhySimCode, IRIS)가 입력·산출물·채점 방식을 전부 다르게 정의해 N개 메소드 × M개 벤치마크 평가에 N×M개의 전용 어댑터가 필요했다. Real2SimLab은 메소드가 내놓는 "프로그램"을 공통 인터페이스로 고정해 N+M 통합으로 줄이고, 원 벤치마크의 scorer는 그대로 유지한다. 47개 코딩 에이전트와 5개 non-agent 메소드, 6개 벤치마크+합성 스위트를 지원하며, 오염 없는 학습 데이터·보상 생성 파이프라인도 함께 제공한다.

## 핵심 기여
- 산출물(프로그램)을 메소드-벤치마크 공통 인터페이스로 고정: 메소드별 어댑터(공개 데이터→프로그램)와 벤치마크별 어댑터(데이터→과제+원 scorer 유지)로 N+M 통합 달성
- Build→Freeze→Re-run→Score→Report 파이프라인: 세션 중 산출물이 아니라 동결 후 재실행한 결과를 채점해 세션 특수성을 배제; session-consistent / reproducible 두 기준으로 신뢰성 체크
- reproduction protocol 도입: 공식 scorer가 프로그램 출력에 적용 불가능한 경우(합성 스위트, IRIS, 사용자 영상)를 위해 reproduction skill = 1 - e/e_static 정의
- 학습 데이터 파이프라인: 프레임 썸네일 기반 오염 탐지(재인코딩·리사이즈·클리핑·프레임레이트 변경까지 감지)로 평가-학습 데이터 분리, 평가와 동일 코드로 보상 계산
- 47개 에이전트는 Harbor 브릿지로, Codex/Claude Code/Gemini CLI/OpenCode/mini-SWE-agent 5개는 직접 어댑터로 연결; 오염 탐지가 실제로 PhysCodeGym-Physics IQ 간 27개 중복 클립을 발견

## 한계
- 47개 에이전트를 실제로 돌린 리더보드/비교 결과가 논문에 없음 — "플랫폼 설계"에 집중하고 메소드 비교는 후속 연구로 미룸
- 학습 데이터·보상 파이프라인은 설계만 제시, 실제 학습으로 성능이 오르는지는 검증되지 않음("아직 이 방식으로 모델을 학습시키지 않았다"고 저자가 명시)
- "프로그램을 동일하게 재실행" 원칙에 예외 존재: Video2World 패키지는 Real2SimLab이 직접 재실행하지 못하고 공식 코드에 의존 → 통합 비용이 완전히 N+M으로 수렴하지 않을 가능성
- IRIS는 8개 클래스 중 공 낙하 클래스 1개만 어댑터 지원, 선정 기준 불명
- reproduction skill(정적 베이스라인 대비 상대 오차)이 장면 난이도가 다른 벤치마크 간에도 동등하게 비교 가능한지는 불분명
- 오염 탐지가 가장 심하게 압축된 복사본(40개 중 4개)은 놓침 — 완벽하지 않음을 저자도 인정
