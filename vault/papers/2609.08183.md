# 라우팅 로그가 곧 훈련 데이터다 — NeoHorse-1: Towards Recursive Self-Improvement via Agentic Post-Training with Routing Harness

> 원제: 라우팅 로그가 곧 훈련 데이터다 — NeoHorse-1: Towards Recursive Self-Improvement via Agentic Post-Training with Routing Harness
> 리뷰: [블로그 전문](https://rina-oo.github.io/posts/2609.08183/)

## TL;DR
멀티모델 라우팅 하니스(C0~C3 tier)의 서빙 로그를 그대로 재사용해 에이전틱 post-training 데이터·커리큘럼·재분배 신호를 전부 뽑아낸 리포트. 라우터가 매긴 난이도 추정치를 SFT 커리큘럼 순서와 on-policy distillation(OPD)의 컨텍스트 스케줄 양쪽에 재사용하고, 평가 deficiency profile로 다음 학습 mixture를 재조정하는 evaluation-selection-update 루프를 구성. 4B/9B NeoHorse-1을 10개 벤치마크에서 평가해 매크로 평균을 각각 58.94→64.87, 65.60→69.04로 개선. RSI라는 표현을 쓰지만 실제로는 이 루프를 한 바퀴만 실행한 초기 프로토타입.

## 핵심 기여
- trajectory/user turn/subscene 3단 granularity로 라우팅 로그를 조직하고, 구조 검증(complete/recoverable/quarantined) → 6차원 semantic judge(PASS/WARN/FAIL/NOT_EVALUATED) → Scene·Goal·Outcome 라벨링을 거쳐 학습 데이터로 정제하는 파이프라인
- 라우터의 tier 배정 $k_i$와 tier별 지지도 $\pi_{i,k}$로부터 hard/soft ordering score $s_i$를 정의해, loss 재가중이 아닌 3단계 SFT 커리큘럼 순서 결정에만 사용 (실제 서빙된 모델 정체성이 아니라 요청·이력에서 재추정한 난이도를 씀)
- 같은 순서 점수를 on-policy distillation의 시작 컨텍스트 스케줄에도 적용(routing-guided OPD): top-K+1 bin으로 coarsen한 분포에 대해 response-normalized reverse-KL 최소화, rollout 체크포인트를 계속 갱신
- 평가 결과(subscene 속성·품질차원·라우팅 tier별 deficiency profile)로 다음 이터레이션 학습 mixture 배분을 바꾸는 capability-guided allocation → evaluation-selection-update 루프 완성
- 대조 실험: 동일 커리큘럼 하에서 라우팅-하니스 데이터가 공개 tool-agent 데이터(Toucan) 대비 5개 벤치마크 평균 +6.26pt; 9B가 4B보다 "실패 후 전략 전환" 궤적에서 우위(요청수/시간/토큰 각 -70.8%/-76.7%/-83.6% 사례)

## 한계
루프를 한 이터레이션만 실행해 반복 시 이득이 누적되는지는 미검증(제목의 "Recursive"가 아직 설계 수준). 에이전틱 카테고리 6개 벤치마크 중 다수(QwenClawBench, WorkBuddy Bench, PinchBench)가 생소하고 일반적으로 검증된 공개 리더보드가 아님. VitaBench(논문 강점과 가장 가까운 멀티턴 서비스 시나리오)에서 두 체급 모두 상위 경쟁 모델에 밀리는데 원인 분석 없음. 비교 표에 자체 측정치와 경쟁 모델의 공식 블로그 self-report(*)가 섞여 있어 평가 조건 편향 가능성. 6차원 semantic judge의 구체 구현(judge 모델, 신뢰도 검증)이 본문에 불명확. 학습 코드·가중치의 실제 공개 여부를 논문만으로 확인 불가.
