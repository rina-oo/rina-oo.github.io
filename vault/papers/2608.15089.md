# 모델은 그대로, 하니스만 갈았다 — StateM: 상태 기계로 CLI 에이전트의 장기 실행을 통제하다

> 원제: 모델은 그대로, 하니스만 갈았다 — StateM: 상태 기계로 CLI 에이전트의 장기 실행을 통제하다
> 리뷰: [블로그 전문](https://rina-oo.github.io/posts/2608.15089/)

## TL;DR
모델 가중치를 하나도 안 건드리고 GPT-5.5의 Terminal-Bench 2.1 점수를 83.1%에서 92.1%로 끌어올린 StateM을 리뷰한다. YAML 상태 기계로 에이전트의 실행 상태를 외부화하고, 전이마다 검증을 강제해 "모델은 할 줄 아는데 하니스가 놓친" 실패를 잡는다.

## 핵심 기여
- StateM: 에이전트 실행 상태를 모델 컨텍스트 밖 YAML 상태 기계로 외부화하는 런타임. 상태 진입 시 `in_hook`이 컨텍스트를 새로 주입하고, 전이 전 `before_transfer`가 검증을 강제한다.
- `goto` 전이 프로토콜: 엣지 존재 확인 → before_transfer 체크 → out_hook 실행 → 엣지 가드 평가 → 커밋(모두 통과 시만) → 목표 상태 in_hook. 실패하면 원래 상태에 머물고 실패가 기록된다.
- 체크 증거력 구분: command/predicate(독립 재현 가능) > manual(사람 결정) > checklist/message(자기 진술) > llm_review(의미 판단이지만 결정론적 검증 아님). 자기 진술을 증명으로 취급하지 않는 설계.
- 세 가지 실패 유형 분류: epistemic gap(지식 부재) / procedural-compliance gap(절차 미이행) / procedural-memory gap(경험 미보존). 각각 in_hook / 체크·전이 가드 / practice(버전화된 재사용 교훈)가 대응.
- 전이 계층 실증: 같은 모델 하니스 개선(GPT-5.5 83.1%→92.1%) → 같은 GPT 세대 내 런북 무수정 전이(GPT-5.6 Sol 84.9%→95.28%) → 다른 제공사 적응 전이(DeepSeek 82.7%→88.1%, $37 적응 비용) → 다른 태스크 일반화(BusinessBench, 매칭된 두 패밀리 +10.04점, 안 맞는 패밀리는 오히려 손해).

## 한계
- 논문 자체가 인정: 보고된 성능은 제네릭 런타임과 벤치마크에 맞춰 진화한 특정 런북(제어 프로필)의 결합 결과. 상태 기계 틀 자체의 기여와 태스크별 체크리스트의 기여를 분리하는 ablation이 없음.
- 헤드라인 95.3%는 리더보드에 병합되지 않은 공개 제출 PR의 raw(조정 전) 점수. 저자 스스로 밝힌 조정 시나리오로는 93.26%~94.38%까지 낮아질 수 있음. 제목이 최댓값을 대표값처럼 제시.
- GPT-5.5 참조 점수는 다른 에이전트 버전(0.125.0)의 공개 참조값이고 StateM 런은 다른 버전(0.144.1) 사용 — 엄격한 버전 매칭 A/B 통제가 아님.
- 잘못된 실행 경계에 통제를 붙이면 오히려 손해(RefactorBench -2.78, WooCommerce -3.70). 프로필 설계 실력에 결과가 크게 좌우됨을 시사.
- WebArena 패밀리는 사실상 무승부(개발 2승10무0패, held-out 0승12무1패)였고 제안된 개선안은 아직 미평가 상태로 남음.
