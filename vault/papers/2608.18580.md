# FACET: Preserving Source Intent and Executable State in Terminal Task Synthesis

> 원제: FACET: Preserving Source Intent and Executable State in Terminal Task Synthesis
> 리뷰: [블로그 전문](https://rina-oo.github.io/posts/2608.18580/)

## TL;DR
터미널 에이전트 학습용 태스크(명령·환경·정답·검증기)를 합성할 때 네 아티팩트가 서로 다른 가정에서 생성되면 태스크가 깨진다는 문제를 다룬다. 텍스트 명세 전달 대신, 실제로 빌드된 Docker 컨테이너 상태를 네 아티팩트 생성기가 공유하는 executable-state grounding을 제안한다. 71K 스킬에서 시나리오를 재구성해 6,078개 검증된 태스크를 만들고, 그중 성공 궤적 1.2K개로 Qwen3.5 4B/9B/27B를 SFT해 Terminal-Bench 2.1에서 각각 +7.12/+8.24/+6.75점 개선을 얻었다. 27B 모델(47.57)은 15배 큰 397B 베이스(49.06)에 근접한다.

## 핵심 기여
- Agentic scenario reconstruction: 스킬을 곧바로 태스크로 변환하지 않고 5단계(skill analysis → scenario exploration → association/filtering → evolution/recovery → information expansion)를 거쳐 goal/context/capability/state/io-tool 다섯 차원의 시나리오로 확장한 뒤 solution reference와 instruction reference를 함께 생성.
- Executable-state-grounded construction: 환경을 먼저 빌드·검증(최대 3회 리페어)하고, 그 결과로 관찰된 초기 상태 $e_0$를 instruction/solution/verifier 생성기가 read-only로 공유. 실행(정답 구동, 검증)은 항상 깨끗한 새 컨테이너에서 수행해 디버깅 컨테이너를 그대로 채택하는 오염을 차단.
- Forward($I\to S\to V$) vs Reverse($I\to V\to S$) vs Joint(단일 호출) 비교: 100개 공통 시나리오로 초기 유효율 46.5% vs 24.2% vs 37.5%. Forward가 Reverse보다 유의미하게 우세(p=0.0017)하지만 Joint 대비는 약한 증거(p=0.233). Reverse는 계약 불일치(56.5%)가, Joint는 fixture/schema/path grounding 실패(38.3%)가 지배적.
- Targeted repair: 실패 원인(환경/정답/검증기/명령)을 라우팅해 해당 아티팩트만 재생성, 유효한 컴포넌트는 보존. 태스크 레벨 최대 5회 리페어.
- 500개 공통 스킬쌍 기준 파이프라인 어블레이션에서 FACET의 validated yield 70.0%로 Baseline(15.6%), TW 재구현(27.8%) 압도. 동시에 FACET 잔존 태스크가 P@1·P@3 최저, 평균 명령어 수 최다 — yield 상승이 태스크 난이도 하락에서 온 게 아님을 시사.

## 한계
- TW(TerminalWorld) 비교 베이스라인을 저자들이 직접 재구현했다는 점에서 완전히 중립적인 비교로 보기 어려움(저자도 인정).
- SFT 데이터가 1.2K 궤적뿐이라 데이터 효율적이라는 주장은 성립하나, 6,078개 검증 태스크 중 성공 궤적(20.94%)만 활용하고 나머지 실패 궤적(체크레벨 89.40% 통과)의 부분 성공 신호는 버려짐. RL 활용은 future work로 남김.
- Forward 우위 주장의 핵심 통계적 근거는 Reverse 대비(p=0.0017)이며, 더 직접적인 대안인 Joint 대비는 p=0.233으로 결정적이지 않음 — 서사가 근거보다 강하게 기울어 있음.
- 스킬 태그별 통과율(Figure 4)의 Wilson 95% 신뢰구간이 대부분 넓게 겹침 — 표본 크기(n=44~192) 한계로 태그 간 난이도 차이를 인과적으로 해석하기 어려움(저자도 서술적 지표로만 제한).
- 환경 빌드·검증·리페어를 포함한 전체 파이프라인 비용은 정량화되지 않음(아티팩트 생성 단계의 분당 비용만 부록에 짧게 언급).
