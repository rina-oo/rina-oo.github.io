# RRSI: Regularized Recursive Self-Improvement of Agent Harnesses

> 원제: RRSI: Regularized Recursive Self-Improvement of Agent Harnesses
> 리뷰: [블로그 전문](https://rina-oo.github.io/posts/2609.24972/)

## TL;DR
LLM이 harness(프롬프트·제어흐름·도구·메모리)를 스스로 반복 수정하는 recursive self-improvement(RSI) 루프는 유한한 evolve set을 라운드마다 재사용하는 adaptive reuse 구조라 과적합에 취약하다. 실제로 evolve set 점수는 오르는데 OOD held-out에서는 정체되거나 퇴보하는 baseline 4개를 실증으로 확인했다. RRSI는 고전 정규화(L0/L1/L2)를 제안(annealed edit budget, evidence-aware credit assignment, structured exploration)과 선택(leakage screening, noise-adjusted floor, cost-aware acceptance, structural pruning) 양쪽에 유비로 이식해, evolve set 향상폭은 가장 작지만 8개 벤치마크 6개 held-out split 전부에서 baseline을 앞지르고 토큰 비용도 30% 줄인다.

## 핵심 기여
- harness 진화를 $H=(\pi,H)$ 위의 adaptive empirical optimization으로 정식화하고, evolve set 재사용이 과적합을 유발한다는 걸 Figure 1(evolve-split 향상 vs OOD 향상 산점도)로 실증.
- 제안 쪽 규제 3종: 라운드마다 허용 수정 개수를 코사인 스케줄로 줄이는 annealed edit budget($L_0$ 유비), 과거 라운드의 채택/기각 이력을 전부 조건화하는 evidence-aware credit assignment, 탐색 정체 시 미탐색 컴포넌트로 예산을 돌리는 structured exploration.
- 선택 쪽 규제 4종: 평가 전 벤치마크 특정 로직을 걸러내는 leakage screening, 역대 최고 대비 노이즈 폭 이내로만 퇴보를 허용하는 noise-adjusted floor, 비용 증가를 측정된 성능 향상만큼만 허용하는 cost-aware acceptance rule($\Delta C \le \beta_0+\beta_1\Delta S$, $L_2$/Ridge 유비), 최근 기여 없는 컴포넌트를 삭제 대상으로 지목하는 structural pruning($L_1$/Lasso 유비).
- coding/agentic workspace/engineering design 3도메인 8벤치마크에서 evolve-split 향상은 가장 작으면서 6개 held-out split(ID+OOD) 전부 무퇴보 향상, OOD 평균 최대 +4.7점(13.1%), 정책 토큰 비정규화 대비 30% 절감을 달성.
- 정책 모델(Claude Opus 4.8 ↔ Gemini 3.5 Flash)과 진화에 참여하지 않은 소형 모델(Gemini 3.1 Flash Lite)에도 전이가 재현되어, harness 개선이 특정 백본에 종속된 아티팩트가 아님을 확인.

## 한계
논문이 인정한 한계: 백본 가중치는 고정한 채 harness만 진화시키는 세팅만 다룸(가중치 동시 업데이트 세팅에는 미검증); 여전히 유한 evolve set과 다수의 정규화 하이퍼파라미터($\delta, b_{\min}, b_{\max}, \beta_0, \beta_1$ 등)에 의존해 피드백 품질·탐색 예산에 효과가 좌우될 수 있음; 훨씬 다른 아키텍처·도구 생태계·더 긴 자기개선 과정으로의 일반화는 추가 검증 필요.

리뷰어 지적: (1) 정규화 하이퍼파라미터가 도메인마다 다르게 설정되어 있고(부록 Table 5) 민감도 분석이 없어, 이 값들 자체가 또 다른 수동 튜닝·과적합 지점일 가능성이 있음. (2) ablation이 제안/선택 두 그룹 단위로만 나뉘어 있어 leakage screening·noise floor·cost rule·pruning 중 개별 장치의 기여도를 분리할 수 없음. (3) Figure 1에서 RRSI는 evolve-split 향상폭이 가장 작은데 OOD 향상폭은 가장 커서 1:1 전이선을 크게 웃도는 "증폭" 패턴을 보이는데, 반복 진화 실행에 대한 분산(에러 바) 정보가 없어 이 폭의 안정성을 판단하기 어려움.
