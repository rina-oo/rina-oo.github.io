# HexaShell: A Thin Harness for Exploring the Limits of VLM Agents as Robot Coding Agents

> 원제: HexaShell: A Thin Harness for Exploring the Limits of VLM Agents as Robot Coding Agents
> 리뷰: [블로그 전문](https://rina-oo.github.io/posts/2610.23479/)

## TL;DR
코딩 에이전트(Codex + GPT-6-Astra)에게 로봇을 조작하는 명령어 한 줄(robo)만 주는 얇은 harness를 만들고, acting agent가 실패하면 optimizer agent(같은 모델)가 실패 로그·프레임·코드를 읽고 "도구"(물체 측정·동작 보조용 작은 파이썬 프로그램)를 고쳐 다음 에피소드에 재사용하게 하는 시스템. 깊이 센서 없이 캘리브레이션된 카메라의 삼각측량·평면교차만으로 3D 위치를 측정하며, 이 방식이 단안 깊이 추정 네트워크보다 정확하다는 걸 보임. RoboDojo 42개 과제 전체에서 성공률 39.7%, progress score 48.0으로 학습 기반 정책(VPP2 32.3%, PhysicalRSI 31.4%)을 넘어서는 신기록을 세움. 밀기(92.5%)·기억(65.0%) 과제는 강하지만 정밀 삽입(8.3%)은 약함 — 한계가 "추론"이 아니라 "접촉"에 있다는 게 핵심 주장.

## 핵심 기여
- 얇은 harness + 짧은 수리 루프: 코딩 에이전트는 바꾸지 않고, 모든 학습 결과를 "작은 도구 + 유닛 테스트"로만 남겨 다음 에피소드가 로드. 실패 후 한 라운드는 중앙값 6.3분, 로봇 데이터·학습·모델 변경 불필요
- 삼각측량이 깊이 네트워크보다 정확: 같은 하네스·루프·모델로 비교 시 8.7점 높음(리더보드 지표), 레이아웃 단위 57승 23패(McNemar p<0.001). 단 2차 시점 확보에 실행 스텝의 3.6%를 씀(깊이 네트워크는 0.7%)
- VLM 로봇 에이전트의 현재 경계를 과제 유형별로 지도화: 420개 재시험 에피소드 기준, 성공은 "에이전트가 읽거나 기억해야 하는 것"이 아니라 "필요한 접촉 종류"를 따라감. 클러터(13~18개 방해물 추가)는 영향이 적어 성공의 95% 유지
- 7개 사례 연구로 optimizer의 수정 과정을 직접 추적: 대부분 이미지를 안 보고 로그·코드만으로 원인 진단 (측정 오차 → 계획은 맞는데 실행이 어긋남 → 코드 수정 → 다음 시도 성공) 패턴이 반복됨
- 발행 후 감사(audit)로 7개 과제 도구가 벤치마크 자산에서 고정 수치를 쓰고 있었음을 발견, 측정으로 교체 후 재보고(모두 0/10으로 하락) — 투명성은 높으나 최종 수치에 반영 범위가 명확하지 않음

## 한계
- 접촉이 많이 필요한 과제(정밀 삽입 8.3%, 관절체/도구사용 7.5%)에서 근본적으로 약함: 도구가 "한 번 측정하고 미리 계획한 동작을 실행"하는 방식이라, 접촉 중 피드백으로 수정하는 학습 기반 정책과 반대 프로필을 보임
- 실패의 57%는 스텝 예산 소진(agent가 실패를 인지하지만 고치지 못함), 기억 과제는 실패의 50%가 "선언했는데 checker가 틀렸다고 판정"(인지 오류) — 두 유형이 서로 다른 근본 원인을 가리킴
- acting agent와 optimizer agent가 동일 모델이라 "도구 작성 능력"과 "도구 사용 능력"이 분리되지 않음; 다른 모델 조합에서도 결론이 일반화되는지 미검증
- 사례 연구 7개는 저자가 선별한 성공 사례 위주 — optimizer의 오진단이나 수정으로 인한 회귀(regression) 비율은 보고되지 않음
- 벤치마크 자산에서 고정 수치를 쓴 7개 과제의 재측정 결과가 본문 39.7%에 반영됐는지 서술이 불명확
- 에피소드당 평균 739초(로봇 동작은 26초뿐, 나머지는 모델 레이턴시) — 실시간 배포가 아니라 연구용 오프라인 개발 설정
