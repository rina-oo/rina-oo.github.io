# 매번 부르지 말고 한 번 구워라 — Compile by Training: Turning Natural-Language Specifications into Local Neural Functions

> 원제: 매번 부르지 말고 한 번 구워라 — Compile by Training: Turning Natural-Language Specifications into Local Neural Functions
> 리뷰: [블로그 전문](https://rina-oo.github.io/posts/2609.04199/)

## TL;DR
자연어 함수 명세를 teacher 모델이 합성한 데이터로 훈련시켜, 공유된 0.6B Qwen3 인터프리터 위의 LoRA 어댑터로 "컴파일"하는 compile by training을 제안한다. PAW의 원샷 amortized compiler를 warm start로 쓰고 추가로 수십 초~1분을 투자해, 원샷 컴파일러가 정확히 못 맞힌 FuzzyBench-Hard 부분집합에서 평균 LEM을 0.224→0.836으로 끌어올린다. 컴파일을 초 단위 API 호출이 아니라 소프트웨어 빌드 단계로 재정의하고, 실제 웹 서비스(강의 사이트 챗봇, 3D 아바타 조종, 영어-Claudish 번역기)로 배포해 여러 컴파일된 함수를 조합하는 사례까지 보여준다.

## 핵심 기여
- 인터페이스를 `p_s = Compile(s)`, `ŷ = Run(p_s, x)`로 분리해, 컴파일 타임(teacher+GPU 의존)과 런타임(로컬, teacher 호출 없음)을 명확히 나눔
- teacher 모델이 명세 s로부터 (입력, 출력) 쌍 데이터셋 D_s를 합성하고 JSON 형식 검증을 거쳐 학습 파이프라인에 투입 — 지식 증류를 사용자 정의 함수 단위로 적용
- 모든 함수가 공유 인터프리터(0.6B) 위의 LoRA 어댑터+스캐폴드로 표현되어 저장 비용이 함수 수에 선형으로만 증가; PAW amortized compiler의 원샷 예측을 초기값으로 삼아 추가 훈련
- teacher 합성과 훈련을 동시에 시작해 임계 경로를 줄이는 스트리밍 컴파일 경로, 작업 큐·GPU 워커·teacher 출력 캐시로 구성된 서비스 아키텍처 설계
- 30개 컴파일된 함수를 트리로 엮은 실제 웹사이트 챗봇(paw-helper), 언어→DSL 변환 3D 아바타 조종기, 영어-Claudish 양방향 번역기로 조합 가능성과 생성형 출력을 시연

## 한계
- FuzzyBench-Hard 자체가 "기존 방법이 정확히 못 맞힌 것"으로 정의된 부분집합이라 가장 유리한 비교 지점일 수 있음 — 전체 벤치마크 대비 개선 폭은 불명
- LEM 지표가 LLM 판정관(GPT-5.5)에 의존하며 128개 라벨로만 검증됨(acc 0.977, kappa 0.946) — 표본이 벤치마크 전체 태스크 다양성을 대표하는지 불확실
- data scaling sweep에서 2400→3600개 구간 성능이 완전히 정체되는 원인이 설명되지 않음(훈련 설정 고정에 따른 인위적 정체인지, 태스크 신호 포화인지 불분명)
- 논문이 스스로 인정: 합성 supervision이 teacher 오류를 상속할 수 있고, 정확성이 보장돼야 하는 응용은 별도 검증/결정론적 경로 필요; 체계적 사용자 연구는 미수행
- 아바타 사례는 44개 수작업 명령으로만 검증되어 표본이 작음; 여러 컴파일된 함수를 대규모로 조합했을 때 개별 오류가 어떻게 누적되는지는 다루지 않음
