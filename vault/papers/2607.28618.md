# 논문이 아니라 '주장'을 검색한다 — AskChem: Claim-Centered Infrastructure for Chemistry Literature Synthesis

> 원제: 논문이 아니라 '주장'을 검색한다 — AskChem: Claim-Centered Infrastructure for Chemistry Literature Synthesis
> 리뷰: [블로그 전문](https://rina-oo.github.io/posts/2607.28618/)

## TL;DR
논문이 아니라 출처가 달린 개별 '주장(claim)'을 검색 단위로 바꾼 화학 문헌 인프라 AskChem을 리뷰한다. 240만 개 claim, evidence graph, Living Taxonomy 구조와 GPT-5.5 grounding 벤치마크, 그리고 공개된 실제 하이브리드 검색 구현까지 함께 살펴본다.

## 핵심 기여
- 검색 단위를 논문에서 claim(원자적 주장)으로 교체. 각 claim은 source DOI + verbatim quote(또는 evidence locator)로 근거를 강제하는 스키마를 가짐
- 같은 claim store 위에 세 구조를 동시에 노출: 코퍼스에서 유도해 안정화한 faceted taxonomy(검색·browse용), claim 간 관계(supports/contradicts/extends/derives_from)를 잇는 evidence graph, 원리 중심 탐색용 Living Taxonomy
- 프로덕션 구현은 FTS5 + dense vector(mxbai 256-d) + taxonomy tree-BFS + paper-level + author 5채널을 RRF(k=60)로 병합 후 인용수 로그 부스팅, cross-encoder rerank, paper diversify까지 거침(논문 본문엔 없고 공개 코드에만 있는 디테일)
- AskChem-Bench(cross-paper 화학 질문 30개)에서 GPT-5.5 grounding 시 DOI 해석률 88.3%→100%, 답변당 검증 DOI 수 18.1개로 5개 비교 시스템 중 최고
- evidence graph 관계 타입 정확도 97.9%(전문가 audit, 148 표본 중 판정 가능 146개 중 143개 일치), 코퍼스 규모 240만 claim / 14.7만 논문 / claim 100% source-grounded
- 코드(MIT)·데이터셋(CC-BY-4.0)·SDK(`pip install askchem`)·MCP 서버까지 전부 공개, self-host 가능

## 한계
- 저자 인정: 코퍼스가 화학 문헌 일부만 커버, abstract 추출이 full-text보다 얕음, claim/relation/taxonomy 배치가 LLM 오류 가능, AskChem-Bench는 groundedness만 측정(사실관계 전면 검증 아님), taxonomy 정규화가 카테고리를 잘못 합칠 수 있음
- taxonomy가 hybrid search recall 신호로 쓰인다면서도 그 신호를 뺐을 때 성능 저하를 보는 ablation이 없음 — 기여도가 정량적으로 분리되지 않음
- 벤치마크 채점 기준이 시스템마다 다름(AskChem은 claim 단위, 나머지는 paper-level 제목/abstract 단위) — 완전히 동일선상 비교로 보기 어려움
- source-grounded 100%는 "인용이 달려 있다"는 뜻이지 "그 인용이 claim을 정확히 뒷받침한다"는 뜻이 아님. claim 자체의 semantic correctness에 대한 대규모 사람 검증은 없음(evidence graph relation type만 감사됨)
- Edison Scientific(비공개 상용 에이전트)이 정량 디테일 양·주제 적합률에서 AskChem을 근소하게 앞섬 — 완승은 아님
