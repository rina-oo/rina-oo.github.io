# 토큰당 KV 캐시 890바이트 — DeepSeek-V4.1-Flash: Pushing the Limits of KV Cache Compression

> 원제: 토큰당 KV 캐시 890바이트 — DeepSeek-V4.1-Flash: Pushing the Limits of KV Cache Compression
> 리뷰: [블로그 전문](https://rina-oo.github.io/posts/2609.19969/)

## TL;DR
DeepSeek-V4.1-Flash는 552B 백본(prefill 8B/decode 16B 활성) 멀티모달 MoE 모델로, 아키텍처·정밀도·배포 전략 세 층위를 동시에 최적화해 토큰당 글로벌 KV 캐시를 890바이트(DeepSeek-V4-Flash 대비 1/4, DeepSeek-V1 대비 437배)로, 영속 캐시는 1/8로 줄였다. long-horizon 에이전트 워크로드에서 연산보다 저장·대역폭이 병목이라는 문제의식에서 출발했다.

## 핵심 기여
- Causal Encoder-Decoder(CED): 디코더 레이어들의 글로벌 KV를 인코더 마지막 층 히든 스테이트에서 프로젝션해, prefill 연산을 사실상 절반($L/2$)으로 줄임. YOCO에서 영감.
- Compressed Sparse Attention 2(CSA2): 레이어를 Full/Reindex/Reuse 세 모드로 정적 배정해 main KV·indexer K·Top-K 인덱스를 레이어 간 재사용. 캐시 공유와 인덱스 재사용을 분리한 게 핵심.
- Hierarchical Sparse Indexer: 첫 Full 모드 층이 만든 후보 풀 안에서만 후속 인덱서가 재스코어링하도록 제한해, 후속 인덱서 비용을 컨텍스트 길이에 무관한 상수로 만듦.
- FP4 main KV 캐시(QAT, MXFP4 E2M1): 기존 FP8 대비 저장 공간을 거의 절반으로.
- SWA Bounded Replay: SWA 상태를 정확히 복원하는 대신 최근 $n_{win}$ 토큰만 리플레이하는 근사로 대체, SWA KV를 영속 캐시에서 아예 제거. 배포 단계의 저장-연산 트레이드오프 재설계.
- 사후학습은 SFT+RL+OPD 표준 레시피 그대로이고, 성능 향상은 전부 데이터 합성·에이전트 환경 구축 파이프라인 스케일링에서 왔다고 주장. Terminal-Bench 2.1·DeepSWE v1.1·CyberGym 등에서 Opus-5, GPT-5.6 Sol급 프론티어 모델과 경쟁.

## 한계
- CED·CSA2·FP4·SWA Bounded Replay 네 가지를 동시에 도입한 뒤 합산 수치만 보고. 개별 컴포넌트를 껐을 때의 ablation이 없어 각각의 기여도를 분리할 수 없음.
- 저자들 스스로 결론부에서 CSA2 선택 오류·SWA 근사 복원이 테스트되지 않은 경계 조건에서 성능 저하를 일으킬 수 있다고 인정. 다만 구체적인 스트레스 테스트 결과는 미공개.
- Table 3의 모델 간 비교에 빈 칸(미평가)이 많아 "1위 개수"로 우열을 매기기 어려움.
- 사후학습 데이터 파이프라인의 구체적 스케일(태스크 수, 환경 다양성 등) 수치가 거의 공개되지 않아 "알고리즘 혁신 없음, 전부 데이터" 주장을 직접 검증하기 어려움.
- 매우 짧은 컨텍스트(4K~16K) 구간에서는 CED 오버헤드 때문인지 V4-Flash보다 오히려 decode FLOPs가 높게 나타나는데 원인 설명 없음.
