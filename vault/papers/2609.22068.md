# 22,575개 중 5,545개만 살아남았다 — CodeMidas: Scaling Agentic Coding RL Environments from Code Itself

> 원제: 22,575개 중 5,545개만 살아남았다 — CodeMidas: Scaling Agentic Coding RL Environments from Code Itself
> 리뷰: [블로그 전문](https://rina-oo.github.io/posts/2609.22068/)

## TL;DR
CodeMidas는 이슈·PR·커밋·기존 테스트·사람이 쓴 설명 없이 소스 코드만을 입력으로 코딩 RL 환경을 자동 생성하는 에이전틱 파이프라인이다. 원본 함수를 지우고 그 자리를 태스크로, 원본 코드를 참조 정답으로 삼아 실행 기반 테스트를 만든다. 22,575개 후보 중 실행 일관성 검사와 세 겹의 rollout 후 필터링(leakage, solution audit, outcome filtering)을 거쳐 5,545개(3,185개 코드베이스, 23개 언어, 15개 도메인)만 남긴다. MiMo-V2.5를 GRPO로 학습시켜 SWE-bench Pro, DeepSWE, ProgramBench, RepoZero C2Rust, Terminal-Bench v2.1 5개 벤치마크 전부에서 성능이 향상됐고, 필터링을 거친 5,545개가 필터링 안 한 8,000개보다 모든 지표에서 더 나은 학습 신호였다.

## 핵심 기여
- 개발 기록(이슈/PR/커밋/테스트/문서) 의존 없이 소스 코드만으로 태스크-환경-검증기 3종 세트를 만드는 파이프라인 제시. 언어 다양성(23개)이 기존 방법 대비 크게 확장됨.
- 테스트 구축 후 별도 재검토 단계를 두어, 원본 코드의 우연한 세부사항(정확한 에러 문구, 내부 구조)에 낚인 assertion을 행동적 체크로 교체하거나 폐기.
- Rollout 기반 후처리 필터 3종: adversarial 탐색으로 leakage 차단, reviewing agent로 검증기의 FP/FN 감사, 전부 성공·전부 실패 태스크 배제(성공/실패가 섞인 난이도만 유지).
- 태스크 스케일(1k/3k/5k)과 품질(필터링 vs vanilla 8k) 분리 실험 — 필터링을 거친 3k조차 필터링 안 한 8k를 앞선다는 것을 보임.
- RL 중 codebase exploration, code drafting, self-verification이 모두 증가하며, 이 행동 변화가 held-out 벤치마크(SWE-bench Pro, ProgramBench, Terminal-Bench v2.1)에서도 재현됨을 확인.

## 한계
- 참조 정답이 실제 오픈소스 코드 그대로이므로, 학습 정책(MiMo-V2.5)의 사전학습 데이터와 원본 코드베이스가 겹칠 경우 "추론"이 아니라 "암기 회상"일 가능성 — 논문은 태스크 인스턴스 중복만 검증했을 뿐 사전학습 오염 여부는 다루지 않음.
- 22,575개 중 75%가 탈락하는 다단계 에이전트 파이프라인의 컴퓨트/비용이 정량적으로 보고되지 않음. 사람 작성 자료가 필요 없다는 대가로 에이전틱 컴퓨트가 크게 늘어나는 트레이드오프가 불명확.
- 필터링 4단계(실행 일관성, leakage, solution audit, outcome filtering) 중 어느 단계가 품질 향상에 가장 기여하는지 분해하는 ablation 없음.
- Reviewing agent 자체의 정확도(사람 재검토 대비 일치율)가 보고되지 않아, 검증기를 검증하는 에이전트가 검증되지 않은 순환 구조.
