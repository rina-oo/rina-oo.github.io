# 채팅창을 버리고 캔버스를 쓰면 — JarvisHub: An Open Harness for Canvas-Native Multimodal Creative Agents

> 원제: 채팅창을 버리고 캔버스를 쓰면 — JarvisHub: An Open Harness for Canvas-Native Multimodal Creative Agents
> 리뷰: [블로그 전문](https://rina-oo.github.io/posts/2607.23588/)

## TL;DR
창작 에이전트의 프로젝트 상태를 채팅 기록이 아니라 편집 가능한 캔버스에 두자는 오픈 하네스. 캔버스가 사용자 작업공간이자 에이전트의 외부 메모리·액션 스페이스가 되며, canvas state → protocol bridge → agent runtime 3계층으로 구성된다. 정량 평가 없이 정성 데모 3건만 제시하지만, "평가 대상을 결과물에서 궤적(trajectory)으로 옮기자"는 제안이 핵심.

## 핵심 기여
- 긴 호흡 멀티모달 창작을 타입 그래프(노드·엣지·콘텐츠·메타·피드백·레이아웃 분리) 위의 에이전트 프로세스로 형식화
- capability manifest + execution grant 계약으로 에이전트가 런타임에 숨은 상태를 따로 유지하지 못하게 강제 — 모든 상태 변화가 protocol bridge를 거쳐 감사 가능
- 피드백을 점수가 아니라 상태 전이의 제어 신호(계속/국소 수리/되묻기/중단)로 재정의
- 턴당 9개 항(요청·상태·manifest·grant·액션·관찰·피드백·수리·다음 상태)의 궤적 기록 — process-level 실패(레퍼런스 무시, 전체 재생성 등)를 가시화

## 한계
정량 평가·베이스라인 비교·ablation 전무 → 캔버스 구조 자체의 기여를 분리할 수 없음. Related Work 섹션 부재. 생성 품질은 외부 모델(GPT-5.5, GPT Image 2, Seedance 2.0)에 전적으로 의존. protocol bridge는 형식 검증일 뿐 창작 판단의 의미적 정확성은 보장하지 않음.
