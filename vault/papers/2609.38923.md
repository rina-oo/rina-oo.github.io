# 진짜 파일로 증거를 남겨야 믿을 수 있다 — GraphForge: Training Working Agents with Graph-Anchored Workspace Synthesis

> 원제: 진짜 파일로 증거를 남겨야 믿을 수 있다 — GraphForge: Training Working Agents with Graph-Anchored Workspace Synthesis
> 리뷰: [블로그 전문](https://rina-oo.github.io/posts/2609.38923/)

## TL;DR
Working agent(파일을 읽고 도구를 조율해 결과물을 만드는 에이전트) 훈련 데이터를 합성하는 5단계 파이프라인 GraphForge를 제안. O*NET 직업 시드로 태스크 방향만 고정하고, 실제로 모은 파일들 사이의 관계를 증거 그래프로 엮어 태스크 문장과 채점 루브릭을 함께 역산하는 것이 핵심. 각 채점 기준이 검증에 필요한 파일(증거 앵커)을 직접 지정해 judge의 임의 채점을 구조적으로 억제한다. Qwen3.6-27B를 2,169개 trajectory로 SFT해 GDPVal +65.7 Elo, Workspace-Bench-Lite +7.7, SpreadsheetBench II +13.7을 달성했고, 파일·텍스트·직업 세 층위 오염 감사로 이 개선이 벤치마크 암기가 아님을 뒷받침.

## 핵심 기여
- 시드(직업·업무·실행패턴)와 실제 파일의 역할을 분리: 시드는 방향만 고정하고, 구체적 태스크·검증 기준은 파일을 모은 뒤 역산
- 증거 그래프 기반 채점 기준 설계: 각 기준 $c_k$가 검증 근거 파일(anchor) $A_k$와 검증 절차 $\phi_k$를 명시해 judge 채점을 파일에 묶음
- 실행 조건부 1회 수정: teacher가 초안 태스크를 한 번 실행해보고 그 결과로 태스크/루브릭을 보정(재사용 가능하면 teacher 재실행 생략, 전체의 81.6%가 재사용)
- 승인 점수 $Q_i(\tau)$ = (양의 기준 가중합 − 음의 기준 패널티) / 양의 기준 가중합 합, 0.90 초과만 SFT 코퍼스 admission
- RFT(rejection fine-tuning)에서 증거-앵커 judge로 선택한 trajectory가 무작위 선택보다 일관되게 우수함을 확인(다만 GDPVal에서는 통계적으로 비유의)

## 한계
- 파이프라인 전 구성요소(워크스페이스 구성, 그래프 생성, 수정, teacher rollout, judge)가 전부 GLM-5.2 하나로 동작 — 데이터 생성자와 채점자가 같은 모델 계열이라 교차 오염(judge가 자기 계열 스타일을 더 관대히 평가) 가능성을 직접 테스트하지 않음
- 크롤링한 공개 파일의 라이선스/저작권 적합성에 대한 구체적 검토 절차가 불명확
- 코퍼스 규모(2,169개)가 타 합성 데이터 파이프라인 대비 한 자릿수 작음(저자 인정 한계). Q>0.90 승인 기준의 엄격함과 직결된 trade-off로 보이나 기준 완화 시 품질 저하에 대한 민감도 분석 없음
- base 모델 두 종(Qwen3.6-27B, 35B-A3B)이 같은 패밀리라 다른 아키텍처/모델 계열로의 일반화는 미확인(저자 인정 한계)
- judge가 구조적 증거 삭제(워크시트 삭제 → Δ−0.377)는 잘 잡지만 숫자·인용 조작 같은 미세 손상(Δ<0.03)은 잘 못 잡음 — 증거 앵커 설계 자체보다 judge 모델의 세밀한 독해력 한계로 저자들도 인정
