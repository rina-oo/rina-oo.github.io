# Skill이 통하는 이유, 통하지 않는 이유 — Agent Skills를 해부한 CAST 분석

> 원제: Skill이 통하는 이유, 통하지 않는 이유 — Agent Skills를 해부한 CAST 분석
> 리뷰: [블로그 전문](https://rina-oo.github.io/posts/2608.14036/)

## TL;DR
에이전트 skill(재사용 가능한 절차 지식)이 왜, 어디까지 통하는지를 raw/workflow-memory/skill 세 조건의 통제 비교와 528개 쌍대 trajectory 분석으로 분해한 논문. 핵심 주장은 skill이 사실 주입(knowledge_injection, 4.5%)이 아니라 절차 안정화(procedural_anchor, 65.7%)로 작동한다는 것. Skill vs workflow memory 비교(+6.06pp, 동일 원본 trajectory에서 표현만 다름)가 skill vs raw(+2.8pp, CI가 0을 포함)보다 통계적으로 더 견고해, 이득이 "경험을 더 줌"이 아니라 "경험을 표준 절차로 증류함"에서 온다는 걸 뒷받침한다. Retrieval 실험은 실사용 precision이 pool 크기 5→100에서 29.6%→3.3%로 붕괴해도 다운스트림 성공률은 36.4%→39.3%로 거의 무영향임을 보여, 정확한 skill 검색이 성공의 필요조건이 아님을 시사한다.

## 핵심 기여
- Raw / Workflow Memory / Skill 세 조건을 동일 trajectory pool(5s0f~0s5f 성공·실패 비율 그리드)에서 통제 비교하는 실험 설계로, "더 많은 경험"과 "다른 표현 방식"의 효과를 분리
- 8,135개 trial을 정규화하고 240개 trajectory를 open-coding해 12-mode(3 상위 카테고리 SC1 성공적 절차 앵커링·SC2 실행/검증 실패·SC3 호출/한계 실패) taxonomy 구축, human validation으로 신뢰도 확보(exact agreement 95.8%, Cohen's κ=0.952)
- Mechanism label(procedural_anchor/knowledge_injection/failure_warning/none/counterproductive) 분석으로 skill의 작동 원리가 절차 안정화(65.7%)이지 사실 주입(4.5%)이 아님을 정량적으로 입증
- Skill 고유의 새 실패 유형(skill_guidance_misapplied_or_ignored, skill-arm 10.0% vs raw 0.8%/workflow 0.4%) 발견 — 절차 압축이 만드는 새로운 실패 표면
- Retrieval을 3개 독립 Arm(embedding 검색/agent 명시적 선택/실제 실행 중 파싱)으로 분해해, "찾아낼 수 있는가"와 "다운스트림 성공"이 서로 다른 곡선을 그린다는 것을 보임 (pool 100에서 actual-use precision 3.3%까지 붕괴해도 성공률은 안정적)
- Cross-framework 전이(Codex→Gemini CLI)에서 skill이 workflow memory보다 프레임워크 종속성을 덜 타고 살아남음을 확인 (skill은 전 mixture에서 raw baseline 상회, workflow memory는 baseline 근처/이하)

## 한계
- 저자 인정: 터미널/도구 사용 벤치마크에 국한(장기 웹 상호작용·개방형 협업 미평가), agent-model 조합이 소수(Codex+GPT-5.3-Codex, Gemini CLI+Gemini-3.1-Pro)뿐, taxonomy가 전체 8,135개 중 약 3%(240개) 샘플의 open-coding에서 유도됨
- RQ4는 GPT-5.3-Codex 접근 불가로 GPT-5.4로 모델을 바꿔 진행 — RQ1-3과 직접 비교 불가, 논문 전체를 관통하는 단일 일관된 모델셋 결론이 아님
- Claude Code 결과가 각주로만 언급되고 실제로는 미제시 — skill 개념을 대중화한 Anthropic 자체 하니스 결과가 빠짐
- 528개 paired triple 전체의 mechanism/mode 라벨링은 LLM judge 의존 (human validation은 238개 raw label의 taxonomy 매핑만 재확인, paired triple 전체를 사람이 직접 라벨링한 것은 아님)
- "왜 통하는가"는 규명했지만 "그래서 어떻게 하면 procedural anchoring을 극대화하는 skill을 자동 생성할지"는 후속 과제로 남김 — 생성 파이프라인 최적화로 이어지는 실험은 없음
