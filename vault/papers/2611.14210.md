# Tree-Ising: Repairing Language Models with Bit-Level Ising Edits

> 원제: Tree-Ising: Repairing Language Models with Bit-Level Ising Edits
> 리뷰: [블로그 전문](https://rina-oo.github.io/posts/2611.14210/)

## TL;DR
MIT 연구(Takehi et al.)가 GPT-6 Astra 에이전트로 Qwen3.5-0.8B의 추론 루프(무한 반복으로 토큰 한도까지 채우는 실패 모드)를 가중치 직접 편집으로 고친 사례를, 자연어 에이전트 판단 없이 수학적 최적화 문제로 재정식화한다. BF16 저장 포맷 자체의 이산 구조(state tree: 공유 지수 + 4비트 상태)를 편집 변수로 삼아, "루프 방향 억제 + 정상 토큰 출력 보존 + 희소성"을 목적함수로 세우고 출력 행(row) 단위의 독립적인 QUBO(Ising 모델)로 정확히 분해한다. GPU 시뮬레이티드 어닐링/바이퍼케이션으로 풀어 에이전트 편집(MATH-500 51.7%, $312, forward pass 50회)보다 더 정확하고(54.6%) 훨씬 싸게($0.90, forward pass 4회) 고치며, 변경 비트 수도 2~4배 줄인다. 레이어 선택·dose 보정 레시피를 참조 편집 없이 Qwen3.5-2B에 그대로 전이해 GSM8K 정확도를 21.6%→69.4%로 올린다. 부록으로 IBM Heron 양자 프로세서에서 8변수 서브문제를 QAOA로 실행하는 proof-of-concept도 포함한다.

## 핵심 기여
- BF16 가중치의 저장 구조(state tree)를 그대로 편집 공간으로 사용. 허용 이동은 부호 반전과 2의 거듭제곱 곱셈뿐이며, 공유 지수·가수는 설계상 변경되지 않음이 보장됨(사후 측정이 아니라 구성상 보장).
- forward pass 통계만으로 "루프 방향 약화 + 결론 방향 강화 + 정상 토큰 collateral 보호 + 희소성"의 목적함수를 정의하고, 통계·후보가 고정되면 출력 행 단위로 정확히(exact) 독립 QUBO/Ising 문제로 분해됨을 증명.
- 포워드 스캔 한 번으로 에이전트가 50회 forward pass·158턴을 들여 찾은 레이어(15, 19)를 재현. 두 모델 모두 해당 레이어가 full-attention 블록이라는 점은 스캔의 일반성보다 아키텍처 공유에서 기인했을 가능성을 저자들 스스로 인정.
- 연속(제약 없는) 닫힌형 해(ROME 유사 rank-1 업데이트)와 비교해, 비슷한 정확도를 내면서도 가중치 변경량이 62배 적음을 ablation으로 입증 — 성능 향상은 목적함수 자체에서, 저장 효율은 이산화·희소화에서 옴을 분리해서 보여줌.
- 레이어 선택과 dose 보정을 에이전트 편집이나 참조 체크포인트 없이 base 모델 통계만으로 수행해 Qwen3.5-2B에 전이 성공 (A100 GPU 1대, 26분).

## 한계
- 에이전트의 공개 로그를 사후 분석해서 설계된 레시피라서, Qwen3.5-0.8B 비교는 엄밀한 "제로베이스 탐색 대 제로베이스 탐색"이 아님(레이어 선택은 에이전트 재현, dose는 에이전트 편집의 1.6배로 보정). Qwen3.5-2B 전이가 이를 일부 완화하지만 "최종 레이어 제외" 규칙 자체가 0.8B 모델 관찰 후 확정된 것이라 완전한 독립 검증은 아님.
- 단일 실패 모드(추론 루프), 단일 모델 계열(Qwen, 동일한 linear/full-attention 하이브리드 구조), 수학 벤치마크에만 평가 범위가 국한됨. instruction-following·일반 언어 능력에 대한 부수 효과 미측정.
- 본페로니 보정 후 12개 비교 중 2개(MATH-500@4, GSM8K)만 통계적으로 유의. 초록의 "5개 벤치마크 전부 앞섬"이라는 표현은 사실이지만 통계적 확실성의 범위보다 넓게 읽힐 수 있음.
- 솔버(어닐링 대 시뮬레이티드 바이퍼케이션) 비교가 각 1회 실행·단일 시드로, 엄밀하게 통제된 실행 시간 비교가 아님을 저자들 스스로 명시.
- 양자 하드웨어 실험은 8변수 서브문제 1건, 양자 우위를 주장하지 않는 proof-of-concept 수준.
- 논문 작성 시점 기준 코드가 아직 공개되지 않음("will be made publicly available shortly").
