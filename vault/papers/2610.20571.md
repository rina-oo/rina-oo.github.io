# 장면은 기억하고, 영상은 검증한다 — Any Time, Any Space (ATAS)

> 원제: 장면은 기억하고, 영상은 검증한다 — Any Time, Any Space (ATAS)
> 리뷰: [블로그 전문](https://rina-oo.github.io/posts/2610.20571/)

## TL;DR
멀티샷 에이전틱 비디오 생성에서 "직전 프레임/텍스트 요약"만 넘기는 기존 방식은 비연속적 요청(멀리 떨어진 장면 재방문, 과거 사건 재현)에 취약하다. ATAS는 정적 지오메트리를 담는 장면 기억과 사건·시간으로 색인된 동적 관측을 담는 사건 기억을 분리하고, 생성된 클립을 곧바로 신뢰하지 않고 필름 리뷰·정합·상태 업데이트 체크를 모두 통과한 관측만 기억에 반영한다. 4개 비디오 생성 백본에서 거의 모든 크로스샷 일관성 지표를 개선했다.

## 핵심 기여
- 월드 스테이트 $\mathcal{W}_t=(\mathcal{S}_t,\mathcal{E}_t)$를 장면 기억(정적 포인트 클라우드)과 사건 기억(장면·사건·시간으로 태깅된 동적 관측)으로 분리
- 스크린플레이를 장소·카메라·시간이 명시된 바운디드 샷 요청 $q_{t,k}=(d,s,\xi,c,\tau,e)$으로 재귀적으로 컴파일
- "필름으로 전달할지($f_t$)"와 "기억에 반영할지($r_t$, $a_t$)"를 독립적인 결정으로 분리 — 셋 다 통과해야만 상태 업데이트, 아니면 필름에는 남되 증거로는 미채택
- 컴포넌트 ablation에서 장면/사건 메모리 도입과 재귀적 컴파일이 가장 큰 증분을 차지하고, 검증 게이트(observation validation, state update check)는 상대적으로 작은 증분 — 게이트는 "성능을 올리는 장치"라기보다 "이미 확보한 이득을 지키는 장치"
- 장면 업데이트는 공간적 일관성(C-Top10)을, 사건 기억은 사건 재현 점수를 주로 끌어올림 — 두 메모리의 역할이 실험적으로 분리됨
- 상태 업데이트 체크는 관대해도(90% 승인) 엄격해도(36% 승인) 품질이 떨어지고 기본 설정(67.4%)이 최적 — 무분별한 수용도 과도한 거부도 둘 다 미래 증거를 줄임

## 한계
- 베이스라인(I2V Extension, VGoT, Mora, MovieAgent, ReCA) 대비 메모리 구축·재구성에 드는 연산 비용이 완전히 공정하게 통제됐는지 불명확 (실행 시간 증가는 보고되나 베이스라인과의 동일 조건 비교는 명시 안 됨)
- Wan 2.7 백본의 VBench에서만 ReCA에 뒤지는데 원인 분석 없음
- Event Recapture의 "Action state" 축에서 유일하게 ReCA(0.700)에 열세(0.688) — 정확한 행동 상태 재현이 약점으로 남음; source-grounded VLM judge 자체도 픽셀 단위 정합을 보장 못함(저자 인정)
- 실험에 쓰인 롱폼 영상이 모두 2분 내외로 짧음 — 포인트 클라우드 기반 장면 기억이 훨씬 긴 영상(10분+)에서도 메모리/조회 비용이 다루기 쉬운 수준으로 유지되는지는 미검증
