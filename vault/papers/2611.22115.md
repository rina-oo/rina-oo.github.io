# 파이프라인을 버리다 — Ascend 8,192장으로 285B를 훈련한 Xing4 기술보고서

> 원제: 파이프라인을 버리다 — Ascend 8,192장으로 285B를 훈련한 Xing4 기술보고서
> 리뷰: [블로그 전문](https://rina-oo.github.io/posts/2611.22115/)

## TL;DR
China Telecom Xingchen AGI Lab의 TeleChat 계열 후속 모델 Xing4 기술보고서. NVIDIA GPU/PyTorch가 아닌 Huawei Ascend 910C NPU + MindSpore로 285B MoE를 8,192장에서 훈련했다. 핵심 주장은 SuperPoD의 토폴로지(내부 고대역폭/외부 저대역폭)를 활용하면 pipeline parallelism 없이 HSDP(hybrid sharded data parallel)만으로 PP 기반 대비 1.49배 빠른 step time을 낼 수 있다는 것. 모델 아키텍처(MLA+DSA+IndexShare, depth-width, DSpark 추론 가속)와 에이전트 RL 인프라(TeleGym)까지 함께 다루는 종합 시스템 보고서. 29B MoE(Xing4.0-29B-A4B)는 HuggingFace에 공개됨.

## 핵심 기여
- HyperParallel-FSDP: SuperPoD 내부 고대역폭을 활용한 zero-copy 통신(파라미터 flatten 없이 개별 텐서 단위 AllGather/ReduceScatter) + 3-way 통신 오버랩으로 PP 제거, 1,024-NPU 기준 36.4s→31.8s(1.14×)
- Owner 기반 분산 Muon: 샤딩된 행렬의 Newton-Schulz 직교화를 모든 rank가 중복 계산하던 것을, 행렬당 owner 1개만 계산하고 P2P로 결과를 scatter하는 방식으로 변경. 28.9s→추가 9.1% 단축
- 0-1 knapsack 기반 fine-grained selective recomputation: 연산자별 실행시간 $t_i$·출력메모리 $m_i$를 프로파일링해 메모리 예산 $M$ 안에서 재계산 생략 대상을 선택. 실행시간과 출력크기가 반비례하는 사례(38ms/193MiB vs 13ms/516MiB)를 실측으로 제시. 6.9% 추가 단축
- DSA 긴 시퀀스 최적화: layer-wise indexer backward(15.2%, 단일 기법 중 최대 효과), Q-block head-tail pairing/동적 비용 기반 pairing, document-aware KV compaction
- 아키텍처: MLA+DSA+IndexShare로 long-context prefill throughput 4.68×(MLA 단독 대비), wider-shallower depth-width(45층) 선택, DSpark 블록 단위 speculative decoding으로 디코딩 throughput 2.67~3.77×
- TeleGym: 이기종 에이전트 하네스(TeleAgent, OpenClaw, Claude Code 등)를 공통 episode 인터페이스로 묶고, disaggregated async 실행 + bounded oversampling + partial rollout으로 trajectory 연속성을 유지한 채 정책 업데이트
- CPU affinity/core isolation: 호스트 스케줄링 지연 제거로 512장에서 1-2%, 8,192장에서 5-10% throughput 개선 — 클러스터 규모가 커질수록 이득이 커짐(straggler 효과)

## 한계
- attention 비교(MLA/DSA/IndexShare)와 depth-width 비교가 Huawei Zhanlu 시뮬레이션 기반이며, 논문 스스로 "실제 production serving보다 낙관적일 수 있다"고 인정. 4.68× 같은 수치의 실측 재현 여부 불확실
- owner 기반 Muon이 연산 순서/배치 변경으로 floating-point 결과를 바꿀 수 있음을 인정하면서도, 수렴 곡선이나 최종 모델 품질에 미치는 영향은 측정하지 않음(step time만 보고)
- 벤치마크 점수가 사실상 전무. 서론에서 언급한 경쟁 모델(Qwen3, GLM-5, DeepSeek-V4 등) 대비 Xing4의 실제 성능 비교가 없어 "효율적인 인프라"와 "좋은 모델"의 연결고리를 이 논문만으로는 확인 불가
- 모든 최적화가 MindSpore+Ascend SuperPoD 토폴로지에 강하게 결합되어 있어 다른 하드웨어로의 이식 가능성은 별도 검증 필요
- DSpark의 benchmark별 가속 편차(HumanEval 2.10× vs LiveCodeBench 1.48×) 원인 분석 없음
