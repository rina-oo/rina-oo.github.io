# '논문 쓰는 AI'가 쓴 '에이전트로 그림 그리는 AI' 지도 — Advances in Agentic Computer Graphics

> 원제: '논문 쓰는 AI'가 쓴 '에이전트로 그림 그리는 AI' 지도 — Advances in Agentic Computer Graphics
> 리뷰: [블로그 전문](https://rina-oo.github.io/posts/2611.01860/)

## TL;DR
agentic graphics system을 "LLM이 행동을 결정 / 그래픽스 환경에서 실행 / 실행 결과 피드백이 다음 행동에 영향"이라는 세 조건으로 엄격히 정의하고, 명세·기반 모델·하니스(플래닝/피드백/메모리)·그래픽스 인터페이스 네 축의 공통 taxonomy를 제시한 Eurographics STAR 서베이. 2024~2026년 9월 사이 300여 편을 사람이 아니라 PaperQA2 스타일 근거 기반 주석 파이프라인을 갖춘 자체 에이전트로 검색·분류·분석해, "local patch 업데이트 비율이 50%→83%로 증가", "documentation & rules 참고 비율이 85.3%까지 증가" 같은 분야 전체의 설계 트렌드를 정량적으로 도출했다.

## 핵심 기여
- taxonomy 네 축: 명세(과제/입력형태/출력형태) · 기반 모델(모델 종류/학습 방식) · 하니스(plan & act — planning/workflow/update strategy, feedback — verifier/feedback signal, memory — time/reach) · 그래픽스 인터페이스(action type/graphics software/tools/representation/resources)
- 논문마다 제각각인 용어(critic/verifier/judge/reviewer 등)를 taxonomy 라벨로 환원해 비교 가능하게 만듦
- 에이전트형 리터러처 서베이 시스템: 논문 발견 → 증거 기반 주석(PaperQA2 방식, 라벨 전에 근거 확보) → 지식 큐레이션 3단계 파이프라인. 라벨·설계 인사이트·한계·근거 위치를 함께 저장해 재사용·재검증 가능
- 코퍼스 분석 결과: update strategy가 과제별로 갈림(CAD는 regeneration 우세, scene generation은 local patch 우세), 시간이 지날수록 local patch와 documentation&rules 의존도가 증가하는 추세 확인
- SubDGuide vs PLAYGROUND 사례처럼, 같은 taxonomy 축(update strategy)으로 두 시스템을 나란히 놓으면 "왜 특정 종류의 오류를 못 고치는가"가 설계 선택 하나로 설명됨을 시연

## 한계
- 분류 전체가 GPT-6 Astra(medium reasoning effort) 기반 자동 주석 결과에 의존. 사람의 사후 검수가 "코퍼스 포함 여부" 수준인지 "라벨 하나하나의 정확성" 수준인지 불명확. 저자들도 지식 큐레이션 단계의 검사가 "누락·불일치는 잡아내지만 분류의 정확성 자체는 검증하지 않는다"고 명시 — 상대적 추세는 신뢰할 수 있어도 절대 비율의 정확도는 불확실
- 에이전트형 서베이 시스템과 300편 코퍼스 자체는 "공개할 계획"이라고만 밝혔을 뿐 논문 시점에는 저장소 링크가 없어 재현·검증 불가
- taxonomy 각 축이 상호 배타적이지 않아 시스템 하나에 라벨이 10여 개씩 동시에 붙음 (Table 1 하니스 항목만 14개) — 분류는 세밀하지만 두 시스템의 유사도를 한눈에 비교할 정량 지표가 없어, 결국 사람이 라벨 목록을 다시 해석해야 하는 수고가 taxonomy 이전과 크게 다르지 않을 수 있음
