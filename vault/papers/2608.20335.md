# N을 O(1)로, 그룹을 계속 섞어라 — 4DAnyone이 '한 대의 폰 영상'을 24대 카메라로 늘리는 법

> 원제: N을 O(1)로, 그룹을 계속 섞어라 — 4DAnyone이 '한 대의 폰 영상'을 24대 카메라로 늘리는 법
> 리뷰: [블로그 전문](https://rina-oo.github.io/posts/2608.20335/)

## TL;DR
카메라 제어 비디오 확산 모델은 소수 시점 생성은 잘 하지만 4DGS 복원에 필요한 수십 개 시점으로 확장하면 일관성이 깨진다. 원인을 "단일 DiT forward pass의 어텐션 컨텍스트가 유한하다"는 아키텍처 제약(bounded-attention-context problem)으로 규명하고, 레퍼런스 컨텍스트를 O(N)에서 O(1)로 압축하는 Reference Context Packing(RCP)과 타겟 뷰 그룹을 노이즈 단계별로 다르게 섞는 Target Context Routing(TCR)으로 해결한다. 여기에 깊이 버퍼링된 3D 스켈레톤 조건화와 자체 게임 엔진 데이터셋(MVGameHuman)을 더해, 캘리브레이션 안 된 단안 영상 한 편에서 4DGS 아바타를 복원하는 파이프라인을 완성했다.

## 핵심 기여
- Reference Context Packing(RCP): FramePack에서 영감을 받은 multi-scale patchify layer로, 누적되는 레퍼런스 뷰들을 mixed-resolution 고정 길이 컨텍스트로 압축. 소스 뷰는 원본 해상도, 오래된/많은 레퍼런스일수록 더 강하게 압축(2배·4배)해 토큰 슬롯 개수를 고정. 오버헤드가 O(1)로 유지됨
- Target Context Routing(TCR): 고노이즈 단계(전역 구조 결정 구간)에는 4-view 그룹을 스텝마다 순환 재편성(rotating)해 그룹 경계 너머로 정보 교환, 저노이즈 단계(디테일 정제 구간)에는 인접 그룹으로 고정. 전환 시점 t_s/T=0.2에서 개선이 포화됨을 스윕 실험으로 확인
- 3D-aware 스켈레톤 조건화: "accuracy over density" 원칙 하에 조밀한 depth 대신 성긴 3D 스켈레톤 사용. 픽셀 단위 z-buffer로 깊이 버퍼링해 2D 스켈레톤의 전후 모호성(occlusion ambiguity) 해소. 스켈레톤 인코더는 zero-initialized residual로 노이즈 latent에 더해짐
- MVGameHuman 데이터셋: 자체 게임 엔진으로 제작한 38k개 멀티뷰 영상(24대 가상 카메라, 318명 액터), DNA-Rendering·SynCamVideo·Pexels·TedTalk와 함께 3단계 커리큘럼 학습에 사용
- 어블레이션으로 RCP·TCR이 상호 보완적임을 확인(Table 3): 라우팅 전략 중 Sliding(지역 인접성 보존)만 세 지표 모두 개선, Random·Strided는 이득 없거나 오히려 저하

## 한계
- 논문 인정 한계: 헐렁한 옷처럼 몸에서 멀리 움직이는 요소는 스켈레톤 신호가 없어 시점마다 다르게 생성됨(Fig.9 좌). HMR이 포즈를 잘못 추정하면(en-pointe→flat feet) 모든 생성 시점이 동일한 오류를 물려받음(Fig.9 우) — "accuracy over density" 원칙의 태생적 한계
- 리뷰어 지적: (1) Round 1/2에서 먼저 생성되는 레퍼런스 뷰 자체가 부정확할 때의 오류 전파에 대한 분석이 없음 (2) ReCamMaster는 저자들이 동일 프로토콜·RCP·TCR로 직접 파인튜닝한 버전(†)인 반면 MV-Performer·TrajectoryCrafter는 공개 가중치 zero-shot이라 표 하나로 절대 비교하기엔 조건이 다름 (3) MVGameHuman은 자체 게임 엔진 데이터로, 코드는 공개되어 있으나 데이터셋 자체 공개 여부는 논문에 명시되어 있지 않아 학습 재현이 어려움
