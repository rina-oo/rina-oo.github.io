# 게임 엔진이 월드 모델의 '컴파일러'가 될 수 있을까 — Agentic Game Development as a Verifiable Trajectory Data Engine for Scaling World Models

> 원제: 게임 엔진이 월드 모델의 '컴파일러'가 될 수 있을까 — Agentic Game Development as a Verifiable Trajectory Data Engine for Scaling World Models
> 리뷰: [블로그 전문](https://rina-oo.github.io/posts/2608.25518/)

## TL;DR
공간 생성(비디오/3D/월드 시뮬레이터)이 정체된 이유를 "검증 가능성 병목(verifiability bottleneck)"으로 정식화한 포지션 페이퍼. 게임 엔진의 충돌/물리/내비메시 체크(dense, grounded)와 개발자의 최종 승인(sparse, authoritative)을 결합한 학습 목표 RLHEV를 제안하고, 이를 학습하는 에이전트형 월드 모델 AWoMo와 개발 궤적 전체를 기록하는 프로토콜 UWDP를 설계했다. 완성된 시스템의 벤치마크 우위보다는, "게임 개발 궤적이 재귀적 데이터 엔진이 될 수 있다"는 falsifiable한 주장을 소규모 파일럿 실험으로 검증하는 데 초점을 둔다.

## 핵심 기여
- 검증자(verifier)를 $V:\mathcal{X}\times\mathcal{Y}\rightarrow\mathcal{R}$로 정식화하고, 엔진의 하드 게이트 $G_j$와 사람 효용 $U_H$를 분리한 제약 최적화 형태의 RLHEV 리워드 정의 (엔진=조밀한 구조적 검증, 사람=최종 권한이라는 역할 분리가 수식 구조에 내장)
- UWDP: $u_t=(b,o_t,s_t,a_t,g_t,v_t,h_t,\rho_t)$ — 최종 자산이 아니라 의도/행동/체크/수리/리뷰 전체를 안정적 오브젝트 ID로 연결한 궤적 프로토콜. 실패→수리 연결을 credit assignment 문제로 학습 가능하게 만듦
- 씬을 픽셀이 아닌 구조화된 프로그램(entities/transforms/materials/physics/scripts)으로 표현해 이해(역방향 사상)와 생성(순방향 사상)을 하나의 표현 위에 통합
- UnitySceneBench에서 Full RLHEV가 전 데이터 규모(40~720)에서 1위 유지, primary score 0.681 (최강 베이스라인 대비 +0.098). Engine-only(RLVR)나 Human-only(RLHF) 단독으로는 Full RLHEV에 못 미침 — 두 신호의 결합이 핵심
- 부록의 source-scaling 실험이 논문 논지를 가장 직접적으로 뒷받침: 타겟 라벨 8개만 노출한 상태에서 최종 스냅샷 특징(Spearman 0.14~0.19)보다 개발 궤적 특징(0.72~0.77)이 소스 규모와 무관하게 압도적으로 우월

## 한계
- 저자 스스로 명시: 실험에 실제 스캔/로봇/real-to-sim-to-real 루프가 없어 게임 엔진 리워드가 물리 세계로 전이된다는 증거로 읽으면 안 됨 (sim-to-real gap은 미해결)
- 실험 규모가 작음 (Unity 학습 720개, 테스트 200개, 8 시드) — best-of-eight 지표와 mean±std 지표를 분리해서 보고할 정도로 저자들도 안정성에 조심스러움
- RLHEV 가중치 $\alpha=0.65,\beta=0.35$가 왜 이 값인지 ablation/근거 없음
- 엔진 리워드의 reward hacking 가능성(C3)을 원론적으로만 인정, 실제 관찰된 우회 사례나 정량 분석 없음
- 크로스 엔진 전이(Unity→Unreal/Godot)는 절대 성능도 낮고 개선폭도 작음(0.25→0.35, 0.15→0.35) — 동일 엔진 내 분포 이동(0.25→0.75)과는 난이도 차이가 뚜렷
- 사전학습 데이터(87,745개 승인 샘플)의 출처가 "developer-authorized"로만 명시되어 비공개 사내 제품 데이터로 추정됨 — 코드는 공개(preview 저장소)했으나 데이터 재현성은 불확실
