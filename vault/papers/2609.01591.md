# 실수까지 닮은 가짜 학생 만들기 — StudentSim: Training LLM-based Student Simulators

> 원제: 실수까지 닮은 가짜 학생 만들기 — StudentSim: Training LLM-based Student Simulators
> 리뷰: [블로그 전문](https://rina-oo.github.io/posts/2609.01591/)

## TL;DR
AI 튜터 학습에 필요한 "학생 피드백"을 대체할 student simulator를 학습하는 프레임워크. behavioral fidelity(그 학생답게 반응하는가)와 guidance responsiveness(지도를 듣고 고치는가)를 직교하는 두 축으로 정의하고, 여러 학생의 sparse 데이터를 pooling해 공통 패턴을 배우는 Stage 1과 개인 데이터로 특화하는 Stage 2의 2단계 LoRA 파이프라인으로 두 축을 동시에 만족시킨다. 체스/L2 영어/수학 세 도메인 60명에서 검증했고, 학습된 시뮬레이터를 튜터 RL의 리워드로 써서 실제 튜터 개선까지 보인 proof-of-concept을 포함한다.

## 핵심 기여
- F(fidelity)/R(responsiveness) 두 축 분해: 기존 state-tracking 모델(Maia2 등)은 F만 강하고 지도 입력 경로가 없어 R이 붕괴, LLM role-play는 R은 되지만 competence paradox로 F가 낮음을 실증
- Stage 1(다수 학생 pooled 학습, 공통 패턴 습득) → Stage 2(개인 데이터로 LoRA 이어 학습, 개인화) 구조. matched ablation(체스, 100명 pooled vs 1명 반복)에서 pooling 제거 시 F 0.5131→0.4602, R 0.9003→0.8276로 하락, pooling이 최적화 예산이 아니라 다양성 자체에서 오는 이득임을 확인
- 도메인별 F/R 연산화: 체스는 top-1 move accuracy, L2는 LanguageTool 기반 오류 밀도 매치(전체 밀도 + 카테고리별 밀도 반반), 수학은 실제 다른 학생 답변으로 만든 4지선다 top-1 accuracy — 표면 유사도(BLEU 등)가 아니라 각 도메인의 "그 학생다움"을 직접 겨냥한 설계
- 체스 60개, L2/수학 각 15명 페어로 StudentSimEval 공개(코드·스플릿 포함) — 새 방법을 같은 held-out 셋에서 바로 비교 가능
- 학습된 StudentSim을 얼려서 튜터 GRPO의 리워드로 사용(r = score(A_rev) - score(A_prev)), open backbone 위에 personalization/perception head를 linear probe로 얹어 closed API 리워드가 못하는 확장을 구현. 사람 평가에서 정확도 90.5%(No-RL 75.7%, GPT-5.4 리워드 71.6%)로 최고

## 한계
- 수학 R 지표가 bf16 비결정성에 민감(315-record 서브샘플에서 같은 체크포인트가 0.565→0.952로 요동), 저자도 인정하고 전체 세트 사용을 권고하나 재현 신뢰성에 의문
- 체스·수학의 multi-turn 지도문(τ) 자체가 GPT-4o/GPT-5.1이 생성한 합성 텍스트 — 정답(m*)은 엔진/정답지로 고정되어 왜곡되지 않지만 지도의 언어 스타일은 실제 교사가 아니라 LLM 스타일 학습일 가능성, 논문에 명시적 논의 없음(L2만 EFCAMDAT 실제 교사 교정 사용이라 예외)
- 튜터 RL 실험은 체스 하나로만 검증된 proof-of-concept, Stockfish라는 정밀한 per-position reward가 있어 가능했던 설계라 자유 형식 응답 도메인(L2·수학)으로의 일반화는 미검증
- EFCAMDAT·FoundationalASSIST는 학술 협약/Responsible Use Agreement가 필요한 게이트 데이터셋이라 코드가 공개되어도 동일 조건 재현은 어려움(Lichess 체스 데이터만 CC0로 접근 용이)
