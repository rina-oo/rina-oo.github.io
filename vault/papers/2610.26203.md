# 화면만 보면 놓치는 것들 — GUI 에이전트의 'Sequential Distraction' 문제 (Focused Omni-Modal GUI Agents)

> 원제: 화면만 보면 놓치는 것들 — GUI 에이전트의 'Sequential Distraction' 문제 (Focused Omni-Modal GUI Agents)
> 리뷰: [블로그 전문](https://rina-oo.github.io/posts/2610.26203/)

## TL;DR
Omni-modal GUI 에이전트는 화면·오디오·비디오·기기 상태·행동 기록을 매 스텝 통째로 받지만, 모티베이션 실험(모달리티별 ablation)에서 인접 스텝 간 지배 모달리티 전환율이 평균 45.3%, 스텝의 90.1%에서 적어도 하나의 모달리티가 방해 요소로 작용함을 확인. 저자는 이를 Sequential Distraction(실행된 행동이 다음 관찰에 재진입하며 매 스텝의 오판이 누적되는 현상)으로 정의하고, 백본·입력을 전혀 건드리지 않은 채 action 생성 직전 K개 위치에 zero-init 잔차를 매 스텝 새로 계산해 더하는 FocusGUI를 제안. action 토큰 NLL만으로 학습하며 모달리티 관련성 라벨은 쓰지 않음. 4개 omni-modal 백본 평균 TM 31.0→64.2, EM 11.2→33.5(3.0배), 기존 최강 보강 기법 대비 TM +30.1.

## 핵심 기여
- Sequential Distraction 현상의 실측 정의: 지배 모달리티가 인접 스텝의 45.3%에서 바뀌고, 94.0%의 에피소드가 적어도 한 번의 전환을 포함하며, 타깃 요소는 화면 면적 중앙값 0.87%에 불과한 희소성
- 구조적 분리: 원본 임베딩 경로($E_t$)는 그대로 유지하고, 채널별 projection → 결정 레퍼런스 $q_t$ 대비 softmax 우선순위 $\alpha_t^{(m)}$ → 64차원 압축 → zero-init 잔차($R_t$)로 action 직전 K=4 위치에 덧셈 주입하는 4단 파이프라인. 상태를 스텝 간에 들고 다니지 않고 매번 재계산
- 이론적 분해(부록): 잔차가 (V) 값 경로로 action primitive 선택을, (A) attention 재배치 경로로만 argument(좌표·텍스트) 교정을 담당함을 증명 — 덧셈(치환 아님)이 왜 중요한지를 설명
- Ablation에서 4개 컴포넌트 모두 TM보다 GP(에피소드 단위 진행률)에 4~5배 더 크게 기여함을 확인 — 단발 정확도보다 궤적 붕괴 방지가 핵심 효과
- 화면 refinement 계열 베이스라인(OmniParser, RegionFocus, DRS-GUI)이 TM은 거의 제자리(+0.9)면서 EM·GP는 오히려 28~35% 상대적으로 악화됨을 12/12 케이스에서 확인 — 공간적 축소가 좌표·텍스트 근거를 함께 삭제하는 부작용을 수치로 입증

## 한계
- 평가가 OmniGUI 단일 벤치마크(708 에피소드, 2,572 스텝)에 한정되어 일반화 범위가 불확실
- 비교 베이스라인(OmniParser, RegionFocus, DRS-GUI)은 애초에 omni-modal 멀티스텝 세팅을 겨냥해 설계되지 않아, 비교의 공정성에 논쟁 여지가 있음
- 그리디 디코딩 기준 평가이며 빔서치/샘플링 하에서도 격차가 유지되는지 불명
- 저자가 인정한 한계: 우선순위 계산이 현재 관찰에만 의존하는 반응적(reactive) 설계로, 다음 스텝에 중요해질 채널을 선제적으로 예측하지 못함
- 잔차 세기 $\gamma$의 구체적 값/스케줄이 본문에 명시되지 않음
