# VLM이 로봇을 '플레이'하게 만드는 인터페이스 — Show-Harness: Just a VLM Agent Can Play Robots

> 원제: VLM이 로봇을 '플레이'하게 만드는 인터페이스 — Show-Harness: Just a VLM Agent Can Play Robots
> 리뷰: [블로그 전문](https://rina-oo.github.io/posts/2609.10522/)

## TL;DR
로봇 액션을 연속값 대신 MV_FWD/GRASP 같은 이산 의미 단위로 정의하고, embodiment별 인터프리터가 이를 결정론적으로 물리 모션으로 변환하는 Show-Harness를 제안한다. 같은 인터페이스 위에서 프론티어 VLM의 zero-shot 제어와 소형 VLM(2B)의 LoRA 파인튜닝을 모두 지원하며, VLA·code-as-policy baseline 대비 태스크/환경/embodiment 일반화에서 크게 앞선다. 같은 액션 공간을 사람도 조작 가능하다는 점을 이용해 GUI 기반 시연 수집 도구 GUMI도 함께 제시한다.

## 핵심 기여
- 액션을 의미 결정(VLM)과 물리 실행(embodiment-specific interpreter)으로 완전히 분리하는 인터페이스 설계. $s_{t+1} = \Pi_E(\mathbf{x}_t + \sigma_t R_E d_a, \exp(\theta_t [R_E r_a]_\times) Q_t)$ 형태로 의미 액션을 결정론적으로 그라운딩.
- Perception/Reasoning/Action 세 단계에 9개 플러그인(Multi-View Guidance, Proprioception, Subtask/Situated Planning, Action Chunking, Adaptive Step, Visual Prompt, Action History, Failure Recovery)을 얹은 모듈형 harness.
- Zero-shot 모드(Gemini-3.1 Pro 등 프론티어 VLM, 파인튜닝 없음)와 파인튜닝 모드(Qwen3.5-2B, LoRA rank-64, 파라미터 3%만 업데이트, 액션은 별도 헤드 없이 VLM 원 어휘로 예측) 두 모드를 같은 액션 공간으로 지원.
- 태스크·환경·embodiment 3축 일반화 실험에서 ZS 89~100%, FT 86~88%로 VLA(π0.5, GR00T)·VLA-centric·code-as-policy baseline(11~65%)을 크게 상회. Sim-to-real 전이에서 VLA는 0%인 반면 FT는 65%.
- 액션 표현 ablation: 임의 기호+명시적 컨벤션이 의미 있는 이름만 쓰는 것보다 나음 → grounding의 핵심은 이름 자체가 아니라 명시적 설명. 설명 없이 기호만 주면 좌우가 뒤바뀌는 "거울상 오류"가 다수 발생(정답률 23.3%).
- GUMI: 동일 의미 액션 공간을 사람 키보드 조작과 컴퓨터-사용 에이전트(스크린샷상 Claude) 양쪽으로 조작 가능하게 만들어 로봇 시연 수집을 GUI로 일반화.

## 한계
- 실제 로봇 평가 규모가 크지 않음(embodiment 2종, 물체 5종, 목적지 2종 중심). 일반화 축은 다양하나 축별 절대 태스크 수는 적음.
- Cross-Task/Cross-Environment 모두에서 FT가 ZS보다 지속적으로 낮은데(89 vs 86%, 100 vs 88%), 이 격차가 데이터 부족 때문인지 2B 모델 용량의 한계인지는 논문에서 깊게 분석하지 않음.
- 인터프리터의 스텝 크기(2cm/4cm)·회전 단위(15°) 등 보정값이 사람이 직접 정한 값이며, 새 embodiment마다 이 보정에 얼마나 수작업이 드는지는 불명확.
- Zero-shot 모드는 폐쇄형 프론티어 API와 스텝당 8~20초의 지연시간에 의존 — 실시간성이 필요한 태스크에는 제약.
- Figure 1의 정성적 데모(옷 개기, 케이크 자르기 등)는 정량 평가표에 포함되지 않아 성공률 불명.
- 병렬 그리퍼 기반 단일/양팔 조작에 한정 평가됨 — 휴머노이드나 dexterous hand 같은 고자유도 embodiment로의 확장은 저자도 향후 과제로 남김.
