## 들어가며

HF Daily Papers에서 100표를 받은 논문입니다. 최근 Kimi Linear, Qwen3.8처럼 softmax attention과 linear attention(정확히는 gated Delta-rule 계열)을 섞은 하이브리드 모델이 많이 나오고 있습니다. linear attention의 장점은 과거 토큰 전체를 고정 크기의 "recurrent state" 행렬 하나로 압축해버려서, 시퀀스가 아무리 길어져도 KV 캐시처럼 메모리가 계속 자라지 않는다는 점입니다.

그런데 이 논문은 "고정 크기니까 메모리 문제가 없다"는 통념을 뒤집습니다. 저자들에 따르면 실제 서빙 환경에서는 동시 요청(concurrent request) 하나하나가 각자의 recurrent state를 들고 있어야 하기 때문에, 컨텍스트 길이가 짧아도 동시 접속자 수가 늘어나면 state 메모리가 선형으로 불어난다고 합니다. 그래서 이 state를 양자화해서 줄이고 싶은데, 단순히 숫자를 낮은 비트로 눌러버리면 정확도가 크게 떨어집니다. 왜 그런지, 그리고 어떻게 고치는지를 다루는 게 이 논문입니다.

## 한눈에 보기

- **핵심 기여**: recurrent state의 양자화 에러가 "시간적으로"(얼마나 오래 기억에 남아있는가)와 "공간적으로"(어느 key row·value column에 있는가) 서로 다르게 영향을 미친다는 것을 수식과 실험으로 보임.
- **방법**: 이 두 축을 반영한 STEPQuant 제안 — 기억 수명에 따라 비트를 차등 배분하는 Lifetime-aware Bit Allocation + key row별 영향력을 반영해 행·열 스케일을 따로 맞추는 Key-Row-Aware Dual-axis Fitting.
- **성능**: Qwen3.8-27B와 Kimi-Linear-48B에서 6비트로도 FP32와 거의 같은 정확도, 4비트에서도 균일 INT8보다 나은 성능. SGLang에 커널까지 올려서 전체 서빙 메모리를 최대 68.7% 절감.
- **한 줄 요약**: "다 똑같이 틀리게 두지 말고, 오래가고 많이 아픈 에러부터 챙겨라"는 꽤 직관적인 아이디어를, 엄밀한 에러 전파 분석으로 뒷받침한 논문입니다.

## 어떤 문제를 풀려고 했나

Gated Delta-rule 계열(Gated DeltaNet, Kimi Delta Attention 등)은 매 토큰마다 recurrent state $S_t$를 아래처럼 갱신합니다.

$$
S_t = (I - \beta_t k_t k_t^\top) D_t S_{t-1} + \beta_t k_t v_t^\top, \qquad y_t = S_t^\top q_t
$$

여기서 $D_t$는 이전 상태를 얼마나 보존할지 정하는 retention gate, $\beta_t$는 새 정보를 얼마나 세게 써넣을지 정하는 write strength, $k_t, v_t, q_t$는 이번 토큰의 key·value·query입니다. 출력 $y_t$는 이 상태에 query를 곱해서 읽어옵니다. 눈여겨볼 점은 이 state가 시퀀스 길이와 무관하게 $d_k \times d_v$로 고정된 크기라는 겁니다.

문제는 서빙 단계입니다. 논문이 측정한 바로는, SGLang에 올린 Qwen3.8-27B 기준으로 동시 요청이 70개를 넘으면 FP32 state 풀의 메모리가 BF16 모델 가중치 전체보다 커집니다. 그래서 이 state를 양자화하고 싶은데, 그냥 균일(uniform) 양자화를 적용하면 4~6비트 구간에서 정확도가 수직 낙하합니다. 저자들은 그 이유를 "에러가 한 번 생기고 끝나는 게 아니라, 매 스텝 state 갱신에 실려서 계속 전파되기 때문"이라고 짚습니다. KV 캐시 양자화와 달리, recurrent state 양자화는 압축한 값이 다음 스텝 계산의 입력으로 다시 들어가는 재귀적 구조라는 게 핵심 차이입니다.

## 핵심 아이디어

### 에러는 왜, 그리고 얼마나 오래 남는가

저자들은 먼저 양자화 에러가 재귀를 타고 어떻게 전파되는지를 수학적으로 정리합니다. 참조(reference) state $S_t$와 양자화된 state $\hat S_t$의 차이를 $E_t = \hat S_t - S_t$라 하면,

$$
E_t = A_t E_{t-1} + \varepsilon_t, \qquad \hat y_t - y_t = E_{t-1}^\top A_t^\top q_t
$$

$A_t = (I-\beta_t k_t k_t^\top) D_t$는 이전 에러가 다음 스텝으로 얼마나 그대로 넘어가는지를 결정하는 전이 행렬이고, $\varepsilon_t$는 이번 스텝에서 새로 생기는 양자화 에러입니다. $\hat y_t - y_t$는 그 결과로 모델 출력에 생기는 에러입니다.

이 식이 말해주는 건 이렇습니다 — retention gate $D_t$가 1에 가까울수록(즉 "오래 기억하는" 채널일수록) 과거 에러가 감쇠되지 않고 계속 끌려온다는 것. 논문은 실제로 Qwen의 2,304개 head를 전부 조사해서, gate half-life(기억이 절반으로 줄어드는 데 걸리는 토큰 수)와 누적된 INT6 양자화 에러 사이에 Spearman 상관계수 $\rho_S \approx 0.80$이라는 꽤 강한 상관을 확인했습니다. 즉 "오래 기억하는 head일수록 에러도 더 크게 쌓인다"는 걸 직접 보인 셈입니다.

이로부터 **Lifetime-aware Bit Allocation**이 나옵니다. 각 유닛(Qwen은 head 전체, KDA는 key row 하나)마다 평균 로그 보존율 $\ell_u$를 측정하고, $H$ 스텝 동안의 에러 잔존을 가중치로 바꿔 비트를 배분합니다.

$$
L_u = \sum_{j=0}^{H-1} \exp(2 j \ell_u), \qquad
\min_{b_u \in \mathcal B_{\bar b}} \sum_u L_u \, d_u(b_u)
\quad \text{s.t.} \quad \sum_u n_u b_u \le \bar b \sum_u n_u
$$

$L_u$는 유닛 $u$의 에러가 미래 $H$ 스텝에 걸쳐 얼마나 오래 영향을 미치는지를 합산한 가중치이고, $d_u(b_u)$는 그 유닛을 $b_u$ 비트로 양자화했을 때 생기는 재구성 왜곡입니다. 평균 비트 예산 $\bar b$ 안에서 $L_u d_u(b_u)$의 합을 최소화하도록 유닛별 비트를 고르는 조합 최적화 문제입니다.

의미 해석을 하자면, 단순히 "에러가 큰 곳에 비트를 더 주자"가 아니라 "에러가 크고 *동시에* 오래 남는 곳에 비트를 더 주자"는 겁니다. 같은 크기의 양자화 오차라도 금방 잊히는 채널이라면 큰 문제가 안 되지만, 반감기가 긴 채널에서는 그 오차가 수백~수천 스텝 뒤까지 출력에 묻어난다는 거죠. 개인적으로는 이 부분이 이 논문에서 가장 설득력 있는 지점이라고 생각합니다 — 단순 heuristic이 아니라 에러 전파식에서 직접 유도된 가중치라는 점에서요.

### 에러는 어디서 더 아픈가

두 번째 축은 공간입니다. 식 (4.2)에서 출력 에러는 각 key row의 영향력을 가중합한 형태로 쓸 수 있는데, 이를 정리하면 row-impact score를 다음처럼 정의할 수 있습니다.

$$
\omega_i = \mathbb{E}_{\mathrm{cal}}[g_{t,i}^2], \qquad r_i = m_i^{1/2} w_i^{-1/2}
$$

$\omega_i$는 key row $i$의 에러가 readout 출력에 미치는 영향을 calibration 데이터로 추정한 값이고, $m_i$는 그 row의 현재 크기(magnitude), $w_i$는 $\omega_i$를 head 내부에서 정규화한 값입니다. $r_i$는 그 row에 적용할 양자화 스케일입니다.

이 식의 의미는 "크기가 큰 row는 넓은 양자화 범위(큰 스케일)를, 영향력이 큰 row는 더 촘촘한 해상도(작은 스케일)를 받는다"는 두 요구를 제곱근으로 절충한 것입니다. 저자들은 실제로 key row를 영향력 순으로 8개 그룹으로 나눠 한 그룹씩만 INT4로 낮춰보는 실험을 했는데, 영향력이 큰 그룹을 낮췄을 때 perplexity가 확실히 더 많이 뛰었습니다 — 즉 "같은 크기의 에러라도 어떤 row에 있느냐에 따라 체감 피해가 다르다"는 가설이 실험적으로 확인된 겁니다. 여기에 더해, state 행렬은 key row뿐 아니라 value column 축으로도 outlier가 따로 존재한다는 걸 보이고(둘의 RMS 비율이 각각 10.3배, 19.4배), 그래서 row 스케일 $r_i$와 별도로 column 스케일 $c_j$를 $w_i^2$ 가중 최소제곱으로 맞추는 **Key-Row-Aware Dual-axis Fitting**을 제안합니다. 한 축만 스케일링하던 기존 LLM 양자화 관행(SmoothQuant 등)과 달리, recurrent state는 두 축 모두에 구조화된 outlier가 있다는 게 저자들의 관찰입니다.

이 두 설계 — lifetime 기반 비트 배분과 key-row 기반 dual-axis scale fitting — 를 합친 게 STEPQuant(**S**patial-**TE**m**P**oral **Quant**ization)입니다. 여기에 더해 가장 위험한 소수 유닛(Qwen head의 1.39%)은 FP16 그대로 보존하는 "pivot" 장치도 둡니다. 전부 offline calibration 단계에서 결정되고 고정되기 때문에, 서빙 중 추가 오버헤드 없이 SGLang 커널에 그대로 녹여 넣을 수 있다는 것도 실용적인 포인트입니다.

표에서 바로 눈에 띄는 패턴은 균일 양자화의 붕괴 속도입니다. INT8까지는 그럭저럭 버티다가 INT6부터 두 모델 모두 평균 정확도가 반토막 이상 나고, INT4에서는 AIME와 HMMT처럼 긴 추론이 필요한 태스크에서 아예 0점이 나옵니다. 반면 STEPQuant는 6비트는 물론 4비트에서도 FP32와 거의 차이가 없습니다 — 심지어 Qwen에서는 STEPQuant@4bit(80.51)이 균일 INT8(71.86)보다 훨씬 높습니다. 같은 비트 예산 안에서 "어디에 얼마나 줄지"를 다르게 가져간 것만으로 이 정도 차이가 난다는 게 인상적입니다. 다만 Kimi(KDA)에서는 4비트일 때 FP32 대비 3점 정도 갭이 남아 있는데, 이는 저자들도 한계로 인정하는 부분입니다.

component ablation도 결과가 명확합니다. Qwen 4비트 기준으로 FP32 84.61 대비, spatial 설계만 쓰면 73.95, temporal 설계만 쓰면 12.87에 그치지만 둘을 합친 STEPQuant는 84.72로 FP32를 오히려 살짝 웃돕니다. temporal 설계만 썼을 때 성능이 특히 낮은 이유는, FP16 pivot 없이 lifetime 가중치만으로는 소수의 "극단적으로 위험한" 유닛을 못 막기 때문이라고 합니다. 실제로 Qwen head의 1.39%만 FP16으로 보호해도 4비트 평균이 6.70점, 6비트 AIME 점수가 14.16점 뛰는 걸 보면, "대부분은 양자화해도 되지만 극소수는 반드시 지켜야 한다"는 전형적인 long-tail 구조가 recurrent state에도 있다는 뜻으로 읽힙니다.

마지막으로 동시 작업(concurrent) DAMP와의 비교도 흥미로운데, DAMP는 9.9비트에서 FP32의 100.99%를 유지하는 반면 STEPQuant는 6.3비트에서 100.51%, 4.3비트에서도 92.91%를 유지한다고 보고합니다. 다만 저자들 스스로 밝히듯 DAMP 코드가 공개되지 않아 재현 비교가 아니라 논문에 보고된 숫자를 그대로 가져와 정규화한 간접 비교이기 때문에, 평가 설정 차이를 감안하고 봐야 할 숫자입니다.

(a)와 (b)를 보면 균일 INT4 양자화에서 생성 길이가 FP32 대비 4~6배까지 늘어나는 걸 볼 수 있습니다(Kimi INT4는 41.1K 토큰으로 FP32의 11.9K보다 훨씬 깁니다). 이건 모델이 답을 못 찾고 계속 "더 생각해보겠다"며 토큰을 쏟아내는, reasoning 모델 특유의 overthinking 현상인데, 정작 정확도는 거의 0에 수렴하니 비효율의 극치인 셈입니다. STEPQuant(@6, @4로 표시된 주황 막대)는 길이가 FP32와 거의 같은 수준으로 유지되는데, 이는 곧 "짧고 정확하게" 답한다는 뜻입니다. (c)는 W4 가중치 환경에서 배치 크기를 512까지 올렸을 때 총 서빙 메모리가 419.73GiB에서 131.18GiB로, 68.7% 줄어드는 걸 보여줍니다. (d)는 그중 recurrent state만 따로 떼어보면 메모리는 80.1%, state 갱신 시간은 65.6% 줄어든다는 걸 보여줍니다. 정확도를 거의 잃지 않으면서 이 정도 메모리·속도 이득을 얻었다는 게 이 논문의 실용적 가치라고 생각합니다.

(a)를 보면 가로축이 동시 요청 수, 세로축이 메모리(GiB)인데, FP32(빨강) 선이 BF16 모델 가중치(파란 점선)를 70개 요청 지점에서 이미 넘어섭니다. STEPQuant(파랑 선)는 기울기 자체가 훨씬 완만해서, 256개 요청에서도 모델 가중치의 절반이 채 안 되는 수준입니다. (b)는 가로축이 gate half-life(로그 스케일), 세로축이 누적 state 에러(로그 스케일)인 산점도인데, 전체적으로 우상향하는 추세가 뚜렷합니다 — 반감기가 긴(오른쪽) head일수록 에러도 큰(위쪽) 경향이라는 걸 한눈에 보여줍니다. (c)는 가로축이 state 비트, 세로축이 7개 태스크 평균 정확도인데, Qwen(진한 선)과 KDA(연한 선) 모두 STEPQuant(원형 마커)가 4비트에서조차 균일 INT(네모 마커)의 8비트보다 높거나 비슷한 위치에 있다는 걸 보여줍니다. 별표로 표시된 FP32 지점과 거의 평행선을 그리는 것도 눈에 띕니다.

## 아쉬운 점 / 의문점

저자들이 직접 인정한 한계부터 보면, lifetime 가중치는 gate decay만으로 에러 잔존을 근사하는데 실제로는 key 방향에 따라 시간 변화하는 state transition이 있어서 이걸 완전히 포착하지는 못한다고 합니다. 또 KDA는 4비트에서 long-generation 태스크 정확도를 다소 잃고, Qwen은 평균 정확도는 FP32에 가깝지만 출력 길이가 길어지는 경향이 남아 있다고 명시합니다.

개인적으로 몇 가지 더 짚고 싶은 부분이 있습니다. 첫째, 평가가 두 모델(Qwen3.8-27B, Kimi-Linear-48B)에 국한되어 있고 둘 다 상당히 큰 모델이라, 더 작은 모델이나 GDN/KDA가 아닌 다른 linear attention 변종(RetNet, Mamba 계열)에도 이 lifetime-에러 상관관계가 그대로 성립하는지는 논문만으로는 알기 어렵습니다. 둘째, calibration에 WikiText-2 32개 세그먼트만 쓰는데, 비트 배분과 FP16 pivot 선택이 고정되어 모든 요청에 재사용된다는 설계상, calibration 분포와 실제 서빙 트래픽의 분포가 크게 다를 경우(예: 코드 생성 위주 트래픽 vs. 일반 텍스트) pivot 선택이 최적이 아닐 수 있다는 의문이 듭니다. 이 부분에 대한 sensitivity 분석이 있었으면 더 좋았을 것 같습니다. 셋째, DAMP와의 비교는 저자들도 인정하듯 재현이 아닌 간접 비교라서, 두 방법을 동일한 평가 프로토콜 위에서 직접 맞붙인 결과가 궁금합니다.

## 마치며

이 논문을 보면서 흥미로웠던 건, "같은 메모리 예산이라도 어디에 쓰느냐가 다르다"는 꽤 직관적인 아이디어를, recurrent state 특유의 재귀적 에러 전파라는 수학적 구조로 정확히 짚어냈다는 점입니다. KV 캐시 양자화에서 쌓인 outlier-aware scaling 노하우(SmoothQuant류)를 그대로 가져오지 않고, "에러가 다음 스텝에 다시 입력된다"는 recurrent 구조의 특수성에서 lifetime이라는 새로운 축을 끌어낸 게 이 논문의 진짜 기여라고 생각합니다. 하이브리드 아키텍처(softmax + linear attention)가 계속 늘어나는 추세를 생각하면, recurrent state 서빙 최적화는 앞으로 더 중요해질 분야일 것 같아서 후속 연구들도 계속 지켜볼 생각입니다.
