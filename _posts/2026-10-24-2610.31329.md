## 들어가며

HuggingFace Daily Papers에서 221 upvotes를 받은 논문입니다. VLM이 "이미지에 뭐가 있는지 말로 설명하는" 일은 이제 꽤 잘합니다. 그런데 "저 사람을 정확히 박스로 짚어줘", "이 물체의 윤곽을 픽셀 단위로 오려내줘", "저 유리컵의 투명한 부분까지 알파값으로 알려줘" 같은 요청으로 가면 이야기가 달라집니다. 박스를 잘 치는 모델이 segmentation은 못 하고, segmentation을 하는 모델은 보통 SAM 같은 별도의 대형 모델을 덧붙여야 합니다. 이 논문은 Tencent WeChat Vision 팀이 detection, referring, counting, pointing, OCR(object-level)부터 segmentation, matting(pixel-level)까지 7개 과제군을 **하나의 VLM + 9.6M짜리 경량 디코더**로 묶어낸 리포트입니다. 2B/4B 두 크기로 공개됐고 코드·가중치가 전부 GitHub에 올라와 있어서(확인해보니 placeholder가 아니라 실제 코드가 들어있었습니다), 실제로 가져다 쓸 수 있다는 점이 눈길을 끌었습니다.

## 한눈에 보기

- **핵심 기여**: (1) 지식 그래프 기반으로 데이터를 능동적으로 수집하고 여러 localization 전문가 모델의 결과를 VLM으로 검증·융합하는 데이터 엔진(WDE), (2) `<OBJ>` 토큰 하나로 박스 예측과 픽셀 예측을 잇는 경량 디코더, (3) 3단계 SFT 커리큘럼 + GRPO 기반 RL로 이어지는 학습 파이프라인
- **성능**: object detection·referring·counting·OCR·referring segmentation·matting 등 30여 개 벤치마크에서 비슷한 크기의 Qwen3-VL/Qwen3.5, 전용 grounding 모델(Rex-Omni, LocateAnything)을 대체로 앞섰고, 특히 "대상이 없을 때 거절하는" rejection 능력에서 격차가 컸습니다.
- **한 줄 요약**: 좌표를 토큰으로, 인스턴스를 `<OBJ>` 토큰 하나로 표현해서 박스부터 알파 매트까지 하나의 autoregressive 인터페이스로 묶어낸 통합 지각 모델입니다.

## 어떤 문제를 풀려고 했나

저자들은 기존 접근을 두 갈래로 나눠 짚습니다. 전통적인 detector(YOLO, DETR)나 open-world 모델(Grounding-DINO, SAM)은 정확하지만 카테고리가 제한적이거나 자연어 지시를 유연하게 못 받습니다. 반대로 최근 VLM들은 말은 잘 알아듣지만 막상 박스를 정확히 치라고 하면 성능이 떨어지고, 특히 밀집된 장면에서 recall이 낮거나 없는 물체를 있다고 우기는 문제(hallucination)가 흔합니다. 그리고 segmentation이나 matting 같은 pixel-level 과제로 가면 대부분의 VLM 기반 연구(LISA, GLaMM 등)가 결국 SAM 같은 별도의 대형 segmentation 모델에 토큰 하나를 넘겨주는 식으로 우회합니다.

WeVisOne-VL의 목표는 이 모든 걸 "구조화된 next-token prediction" 하나로 흡수하는 겁니다. 좌표를 `<0>`부터 `<1000>`까지의 전용 토큰으로 양자화해서 박스·포인트를 직접 생성하게 하고, segmentation·matting이 필요한 순간에는 `<OBJ>`라는 특수 토큰을 하나 추가로 내보내게 합니다. 이 토큰의 hidden state가 바로 픽셀 디코더로 들어가는 "이 인스턴스가 무엇인지"에 대한 표현이 되는 구조입니다. 별도의 큰 segmentation 모델을 덧붙이지 않고도 디코더 하나(9.6M 파라미터)로 박스부터 알파 매트까지 간다는 게 핵심 주장입니다.

## 핵심 아이디어

### 데이터 엔진: 지식 그래프로 수집 방향을 정한다

먼저 이 정도 성능이 나오려면 데이터가 받쳐줘야 하는데, 저자들은 1억 장 이상의 이미지와 36억 개의 바운딩박스 주석으로 구성된 **WeVisOne-VL Data Engine(WDE)**을 따로 만들었습니다.

다음은 WDE 전체 파이프라인을 보여주는 그림입니다.

![WeVisOne-VL Data Engine 개요](/assets/img/posts/2610.31329/fig1_data_engine.png)
_Figure 1. 테디베어·토끼 예시로 보여주는 WDE의 3단계 흐름 — 개념 발견, 로컬라이제이션 검증, 인스턴스 정렬 supervision_

왼쪽부터 순서대로 읽으면 됩니다. ① "Semantic discovery & acquisition"에서는 Tokenize Anything으로 카테고리 개념을, Qwen3-VL로 referring expression(속성·관계로 특정 대상을 지칭하는 문장)을 뽑아내고, 이걸 Wikipedia·WordNet 기반 지식 그래프에 정리합니다. 이 그래프가 "어떤 개념이 부족한지, 모델이 최근에 어디서 틀렸는지"를 추적해서 다음에 수집할 이미지를 결정합니다. ② "Localization & semantic review"에서는 SAM3와 자체 open-vocabulary detector(카테고리 쿼리), SAM3 Agent와 Rex-Omni(referring 쿼리)가 각각 후보 영역을 내놓고, Qwen3-VL이 이 후보들을 이미지와 대조해 선택·중복 제거·충돌 해소를 합니다. ③ "Instance-aligned supervision"에서는 선택된 박스에 SAM2로 마스크를 씌우고, 이 마스크를 다시 matting 엔진(BiRefNet + MatAnyone2로 초기 알파 후보 생성 → 전용 matting annotator 학습 → 전체 코퍼스 재주석)에 넣어 알파 매트까지 뽑아냅니다. 그리고 맨 아래 점선 화살표처럼, 학습된 WeVisOne-VL 자체의 오류를 리뷰해서 다시 데이터 수집·보정 방향을 업데이트하는 피드백 루프가 돌아갑니다. 개인적으로 인상 깊었던 부분은 "no blue car" 같은 부정 쿼리를 다룰 때, 단순히 탐지기가 아무것도 못 찾았다고 바로 negative로 단정하지 않고 사람(또는 모델)이 이미지 전체를 다시 검토해서 진짜 없는지 확인한다는 대목이었습니다 — hard negative를 만드는 데 이 정도로 신중한 검증 단계를 넣는 경우는 흔치 않습니다.

### Task Formulation: 모든 과제를 같은 문법으로

다음은 7개 과제가 입력·출력에서 어떤 모양을 하고 있는지 보여주는 예시입니다.

![태스크별 입출력 포맷 예시](/assets/img/posts/2610.31329/fig2_template.png)
_Figure 2. detection부터 segmentation/matting까지, 모든 과제가 `<ref>`·`<box>`·`<point>`·`<OBJ>` 토큰 조합으로 통일된 포맷을 씁니다_

여기서 눈여겨볼 부분은 맨 아래 segmentation/matting 줄입니다. 다른 과제들은 `<ref>개념</ref><box>좌표</box>`로 끝나지만, segmentation/matting 출력은 박스 뒤에 `<OBJ>` 토큰이 바로 붙습니다("...<902><721><OBJ></box>"). 이 토큰 하나가 뒤에서 설명할 픽셀 디코더를 트리거하는 신호이자 입력입니다. 즉 모델 입장에서는 segmentation이 "detection + 토큰 하나 더"일 뿐이고, 별도의 출력 형식이나 별도의 디코딩 루프가 필요 없습니다.

### 모델 구조: `<OBJ>` 토큰이 어떻게 마스크가 되는가

다음은 픽셀 디코더 내부 구조입니다.

![픽셀 디코더 아키텍처](/assets/img/posts/2610.31329/fig3_model.png)
_Figure 3. Visual Feature Adapter → Box-guided Query Decoder → Instance-Conditioned Dense Prediction, 3단 구성의 경량 픽셀 디코더_

오른쪽 상단의 "Provide the alpha mattes for the people"라는 지시에 대해 VLM이 $b_1, \text{<OBJ>}, b_2, \text{<OBJ>}, b_3, \text{<OBJ>}$ 순으로 세 사람의 박스와 OBJ 토큰을 번갈아 생성하는 걸 볼 수 있습니다. 이 OBJ 토큰들의 hidden state와 박스가 ②번 "Box-guided Query Decoder"로 들어가고, ①번에서 ViT의 여러 레벨 feature를 가공해둔 visual memory와 deformable cross-attention으로 상호작용합니다. ③번에서 각 인스턴스 쿼리가 자기만의 동적 커널을 만들어 공유 픽셀 feature map에 적용하면 인스턴스별 마스크가 나오고, 이걸 3단계로 점점 고해상도로 정제하면서 최종 마스크·알파 매트가 됩니다.

이 흐름에서 핵심이 되는 수식 두 개를 보겠습니다. 먼저 OBJ 토큰이 디코더 쿼리로 바뀌는 과정입니다.

$$q_i = W_h\,h_i, \qquad p_i = \operatorname{MLP}(\phi(b_i))$$

$h_i$는 $i$번째 `<OBJ>` 토큰의 hidden state, $b_i$는 그 직전에 예측된 박스, $\phi$는 Fourier encoding, $W_h$와 MLP는 학습되는 투영입니다. 기존 Deformable DETR류는 쿼리를 학습된 고정 임베딩으로 쓰는데, 여기서는 VLM이 "방금 만든" 토큰과 박스를 그대로 재활용해서 쿼리를 만듭니다. 이미지를 다시 들여다볼 필요 없이, 언어 모델이 이미 뱉은 결과물이 곧바로 디코더의 "무엇을, 어디를" 질의가 되는 셈입니다. 별도의 segmentation 모델이 필요 없는 이유가 바로 이 지점입니다.

두 번째는 마스크가 실제로 그려지는 부분입니다.

$$[k_i,\beta_i]=\operatorname{MLP}(\widetilde q_i), \qquad M_i=k_i^{\top}P+\beta_i$$

$\widetilde q_i$는 deformable attention을 거친 뒤의 쿼리, $P$는 여러 레벨의 ViT feature와 원본 이미지 정보를 합쳐 만든 공유 픽셀 feature map, $k_i$와 $\beta_i$는 인스턴스별로 동적으로 생성되는 1×1 컨볼루션 커널과 바이어스입니다. 모든 인스턴스가 같은 feature map $P$를 공유하면서도 각자 자기만의 커널로 마스크를 뽑아낸다는 게 포인트입니다. 인스턴스 수가 몇 개든 디코더 구조 자체는 바뀌지 않고, 쿼리만 늘어나는 구조라 확장성이 좋습니다.

### 학습 파이프라인: 3단계 SFT, 그리고 "애매한 샘플"만 골라 RL

학습은 3단계 SFT 커리큘럼 뒤에 mixed-task RL이 붙는 구조입니다. Stage 1은 비전 인코더를 얼린 채 90M 예제로 "구조화된 출력을 따르는 법"만 가르치고, 이때 밀집된 샘플(한 응답에 박스 수백 개)이 모델을 반복 출력 collapse로 몰고 가는 걸 막기 위해 카테고리당 최대 50개로 제한합니다. Stage 2는 비전 인코더까지 풀고 해상도(최대 1,960 visual token)와 밀집도(최대 500개 박스)를 올려 작은 물체·crowded scene 대응력을 키웁니다. Stage 3은 픽셀 디코더를 2억5천만 장 segmentation 샘플로 먼저 워밍업시킨 뒤, VLM과 디코더를 NTP(next-token prediction) 손실과 segmentation 손실을 1:1로 섞어 같이 학습시키고, 마지막으로 VLM은 고정한 채 디코더만 1억3천만 장 matting 데이터로 추가 미세조정합니다.

RL 단계에서 재미있는 설계가 "어떤 샘플을 RL에 쓸지" 고르는 방식입니다.

$$U(x)=4\mu_x(1-\mu_x)\sigma_x$$

$\mu_x$와 $\sigma_x$는 SFT 모델이 같은 프롬프트 $x$에 대해 여러 번 응답했을 때 보상의 평균과 표준편차입니다. $\mu(1-\mu)$ 항은 성공률이 정확히 50%일 때 최대가 되고(항상 맞히거나 항상 틀리는 샘플은 걸러짐), 여기에 분산 $\sigma$까지 곱해서 "이 모델이 지금 딱 애매하게 걸려 넘어지는" 샘플만 추려냅니다. 이렇게 뽑은 약 14만 개에 box 지도 샘플과 pointing 데이터를 더해 총 17.8만 개로 GRPO를 돌립니다.

보상 함수도 눈여겨볼 만합니다.

$$r_i=\frac{2\sum_{(\hat b,b^{*})\in\mathcal{M}_i}\operatorname{IoU}(\hat b,b^{*})^{3}}{N_{\mathrm{gt}}+N_{\mathrm{pred}}}$$

예측 박스와 정답 박스를 Hungarian matching으로 1:1 대응시킨 뒤($\mathcal{M}_i$), IoU를 세제곱해서 합산하고 정답 개수와 예측 개수의 합으로 나눕니다. 분모에 $N_\mathrm{gt}$와 $N_\mathrm{pred}$를 동시에 넣은 게 핵심인데, 이러면 놓친 물체(recall 손해)와 중복 예측(precision 손해)이 둘 다 보상을 깎아먹습니다. IoU를 세제곱하는 이유는, IoU 0.5와 0.6의 차이보다 0.9와 0.95의 차이를 더 민감하게 반영하기 위해서라고 합니다 — "대충 맞는" 박스와 "정확한" 박스를 더 뚜렷하게 구분하려는 설계입니다. 흥미로운 건 segmentation·matting 과제조차 RL에서는 박스 기반 보상만 쓴다는 점인데, 이건 뒤에서 다시 짚겠습니다.

Counting은 CountQA·PixMo-Count·CLOC·KubriCount·MixCount 다섯 벤치마크 전부에서 1위를 차지했는데, 특히 세분화된 카운팅을 요구하는 MixCount test에서 40.4%로 2위 LocateAnything(15.2%)보다 두 배 이상입니다. Qualitative 분석에 나온 예시 하나가 인상적이었는데, "가짜 초록 사과" 개수를 세는 질문에서 Rex-Omni는 정답 42개 대신 537개를 보고했다고 합니다 — "비슷한 걸 다 세어버리는" 실패 양상을 단적으로 보여주는 사례입니다. Matting에서는 box 프롬프트 기준 P3M-500-NP에서 MAD 6.6(기존 최고 SAM2-Matting 15.4)으로 절반 이하 오차를 보였고, in-house 벤치마크 WeRefMat의 referring 프롬프트 설정에서도 Qwen3.5-9B+SAM2-Matting 파이프라인보다 MAD 기준 절반 이상 낮은 오차를 기록했습니다.

## 아쉬운 점 / 의문점

몇 가지 걸리는 지점이 있습니다. 첫째, 저자들이 스스로 인정한 한계이기도 한데, segmentation·matting 과제는 RL 단계에서 **박스 보상만** 쓰고 마스크나 알파 매트 자체의 품질은 평가하지 않습니다. 논문에 "RL uses only box-based rewards, without evaluating predicted masks or alpha mattes"라고 명시되어 있는데, 그러면 디코더가 만드는 픽셀 결과물의 품질은 사실상 SFT 단계에서만 다듬어지는 셈입니다. mIoU 같은 마스크 품질 지표를 직접 보상으로 쓰지 않은 이유가 궁금한데, 아마 미분 불가능하거나 설계가 까다로워서였을 것 같은데 이 부분은 논문에 설명이 없습니다.

둘째, 비교에 쓰인 WeRef-Bench, WeRefMat, PR-Bench가 전부 저자들이 직접 만든 in-house 벤치마크입니다. 다른 모델들이 애초에 "대상 없음"을 거절하도록 학습된 적이 없다는 걸 감안하면, 이 벤치마크들에서 보이는 압도적인 rejection 우위가 "더 똑똑해서"라기보다는 "이 능력만 집중적으로 학습 데이터에 넣어서"일 가능성이 큽니다. 엔지니어링 성과로는 분명히 의미 있지만, 공정한 비교인지는 조금 더 따져볼 여지가 있습니다.

셋째, 이 정도 규모의 기술 리포트치고는 ablation이 아쉽습니다. 데이터 엔진의 각 단계(지식 그래프 기반 수집, hard example 구성, 피드백 루프)나 디코더 설계(coarse-to-fine refinement 단계 수, dynamic kernel 방식)가 각각 성능에 얼마나 기여하는지 분리해서 보여주는 실험이 없습니다. 거의 모든 구성 요소를 한 번에 쌓아올린 뒤 최종 숫자만 보여주는 구조라, "어느 부분이 진짜 핵심이었나"를 외부에서 가늠하기 어렵습니다.

넷째, 저자들도 밝혔듯 CoT(chain-of-thought) 추론을 아예 쓰지 않습니다. 추론 효율을 위한 선택이라고 하는데, ReasonSeg처럼 암묵적 추론이 필요한 벤치마크에서 LISA-13B(ft)에 비해 소폭 낮은 성적(val 71.2 vs 65.0은 WeVisOne-VL이 높지만, 다른 항목에서는 밀리는 경우도 있음)을 보이는 걸 보면 이 트레이드오프가 실제로 작동하고 있는 것 같습니다.

## 마치며

좌표를 토큰화하고 인스턴스 하나당 `<OBJ>` 토큰 하나로 픽셀 디코더를 호출한다는 아이디어 자체는 Rex-Omni·LocateAnything 같은 선행 연구의 연장선에 있지만, 이걸 segmentation·matting까지 자연스럽게 확장하면서 "SAM을 덧붙이지 않고" 9.6M짜리 작은 디코더로 끝냈다는 점이 이 논문의 실용적 가치라고 생각합니다. 개인적으로는 데이터 엔진 쪽 설계(특히 hard negative를 다시 검증하는 루프)가 모델 구조보다 더 공들인 부분처럼 읽혔는데, 실제로 rejection 관련 지표들의 격차가 가장 크게 벌어진 걸 보면 그 판단이 맞았던 것 같습니다. 코드와 가중치가 모두 공개되어 있으니, 작은 VLM에 커스텀 segmentation head를 붙이는 작업을 하고 있다면 이 디코더 설계를 그대로 참고해볼 만합니다.
