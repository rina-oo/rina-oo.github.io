## 들어가며

어제 HF Daily Papers에서 120표를 받은 논문입니다. NUS Show Lab(ShowUI, ShowHow 등으로 익숙한 팀)에서 나왔고, 제목부터 도발적입니다. "Just a VLM Agent Can Play Robots" — 로봇 전용 파운데이션 모델(VLA)을 새로 학습시키지 않아도, VLM 하나를 적당한 인터페이스에 꽂기만 하면 로봇을 조작할 수 있다는 주장입니다.

이 논문이 눈에 띈 이유는 최근 로봇 조작 연구의 주류 흐름과 정반대 방향을 택했기 때문입니다. VLA 계열은 VLM을 통째로 로봇 궤적에 맞춰 다시 학습시켜서, 넓은 의미 지식을 결국 "픽셀→모터 신호"라는 불투명한 매핑으로 눌러 담습니다. 반대로 코드-as-policy나 스킬 라이브러리 계열은 VLM이 상위 계획만 세우고 실제 물리 제어는 하위 컨트롤러에 통째로 맡겨버려서, 의미와 물리 사이의 직접적인 연결이 끊깁니다. 저자들은 "그 중간, 그러니까 VLM이 의미상으로도 이해할 수 있으면서 동시에 물리적으로도 충분히 세밀한 액션 공간이 필요하다"고 주장하고, 그걸 구현한 게 Show-Harness입니다.

## 한눈에 보기

- **핵심 기여**: 로봇 액션을 `MV_FWD`, `ROTATE_CW`, `GRASP` 같은 이산적인 의미 단위(semantic action unit)로 정의하고, 이를 embodiment별 인터프리터가 결정론적으로 실제 모터 신호로 변환하는 Show-Harness를 제안했습니다. 같은 인터페이스 위에서 (1) 프론티어 VLM을 파인튜닝 없이 바로 로봇 컨트롤러로 쓰는 zero-shot 모드와 (2) 2B급 오픈소스 VLM을 몇 GPU-시간만 들여 LoRA로 적응시키는 파인튜닝 모드를 모두 지원합니다. 같은 액션 공간을 사람도 조작할 수 있다는 점을 이용해, 키보드/GUI로 로봇 시연을 모으는 GUMI 인터페이스도 함께 내놓았습니다.
- **성능**: 태스크·환경·embodiment 세 축의 일반화 실험에서 zero-shot 모드가 평균 89~100%, 파인튜닝 모드가 86~88%를 기록해, VLA(π₀.₅, GR00T)·VLA-centric 에이전트·code-as-policy 에이전트 baseline들(11~65% 구간)을 모두 크게 앞섰습니다.
- **한 줄 요약**: "로봇 제어를 새로 배우게 하지 말고, VLM이 원래 잘하는 이산적·의미적 사고를 그대로 쓰게 하되 그 결과를 물리적으로 안전하게 변환하는 장치만 붙이자"는 인터페이스 설계 논문입니다.

## 어떤 문제를 풀려고 했나

VLM은 이미 "물체가 뭔지, 공간 관계가 어떤지, 긴 목표를 어떻게 쪼갤지"에 대한 지식을 상당히 갖고 있습니다. 문제는 이 지식이 로봇 행동으로 잘 안 옮겨진다는 점입니다. 저자들은 기존 접근을 두 갈래로 정리합니다.

첫째는 VLA류로, VLM을 embodiment별 연속 액션(관절 각도, end-effector 속도 등)에 회귀하도록 파인튜닝합니다. 이 과정에서 원래 VLM이 갖고 있던 폭넓은 의미 지식이 "픽셀을 넣으면 모터 신호가 나오는" 불투명한 매핑으로 뭉개지고, 새로운 태스크나 embodiment마다 다시 데이터를 모아 재학습해야 합니다.

둘째는 계층적·프로그램적 시스템으로, VLM이 서브태스크 호출이나 제어 API 위의 프로그램 같은 중간 표현을 만들고, 그 아래 컨트롤러가 실제 실행을 담당합니다. 의미는 보존되지만 물리적 실행과의 직접적 연결이 끊기고, 각 표현마다 손으로 짠 grounding 파이프라인이 필요합니다.

저자들의 문제의식은 명확합니다: 파운데이션 모델의 지능을 물리 세계로 가져오려면 "VLM에게 의미적으로 자연스러우면서 동시에 물리 제어에 충분히 세밀한" 액션 공간, 즉 인터페이스 자체가 필요하다는 겁니다. 이게 VLA의 "너무 저수준"과 프로그램적 시스템의 "너무 고수준" 사이의 빈 공간을 채우는 시도입니다.

## 핵심 아이디어

다음은 Show-Harness의 전체 구조를 보여주는 그림입니다.

![Show-Harness의 perceive-reason-act 루프 아키텍처](/assets/img/posts/2609.10522/fig3_method.png)
_Figure 3. Perception·Reasoning·Action 세 단계로 구성된 모듈형 루프. 왼쪽 Perception이 관측을 정리하고, 가운데 VLM이 Reasoning 플러그인이 다듬은 맥락을 받아 하나의 의미 액션을 결정하며, 오른쪽 Action 단계가 이를 실행하고 History로 기억한다_

이 그림에서 중요한 건 화살표 번호 (1)~(5)로 표시된 순환입니다. Perception이 멀티뷰 이미지와 proprioception을 모아 VLM에 넘기면(1), VLM은 Reasoning 플러그인이 정리해준 맥락(서브태스크 계획, 시각적 프롬프트 등)을 받아(2, 3) 딱 하나의 의미 액션을 출력합니다(4). 이 액션이 Action 단계로 가서 실행되고, 그 결과(새 이미지, 실행 상태)가 다시 Perception으로 피드백됩니다(5). 이 루프를 수식으로 쓰면 이렇습니다.

$$
c_t = \Phi_{\mathcal{P}}\!\left(\ell,\, o_t,\, h_t\right), \qquad
a_t = \pi(c_t) \in \mathcal{A}
$$

$\ell$은 언어 지시, $o_t$는 시각·자기수용감각 관측, $h_t$는 상호작용 이력이고, $\Phi_{\mathcal{P}}$는 활성화된 Reasoning 플러그인들이 이 셋을 다듬어 만든 맥락 $c_t$입니다. VLM $\pi$는 이 맥락을 보고 압축된 의미 액션 집합 $\mathcal{A}$ 중 하나 $a_t$를 고릅니다.

여기서 눈여겨볼 부분은 $\mathcal{A}$가 정말로 작다는 점입니다. `MV_FWD`/`MV_BACK`, `MV_LEFT`/`MV_RIGHT`, `MV_UP`/`MV_DOWN`(현재 기준 뷰에 대한 상대적 한 스텝 이동), `ROTATE_CW`/`ROTATE_CCW`(축 지정 회전), `GRASP`/`RELEASE`, `DONE`. 이게 전부입니다. 좌표값도, 관절각도도 없습니다. 저자들은 이 어휘를 세 가지 속성으로 설계했다고 밝힙니다 — (i) *incremental*: 각 단위가 작고 국소적인 물리 변화만 일으켜서 VLM이 매 스텝 결과를 보며 교정할 수 있고, (ii) *interpretable & embodiment-agnostic*: 숫자 목표가 아니라 기호이기 때문에 로봇이 바뀌어도 모델 쪽 어휘는 그대로이며, (iii) *visually grounded*: 방향이 관측 가능한 시점 기준으로 정의돼서 공간 추론이 액션에 그대로 얹힙니다.

의미 액션이 실제 로봇으로 변환되는 부분은 다음 수식이 담당합니다.

$$
s_{t+1} = \Pi_E\!\left(
  \mathbf{x}_t + \sigma_t R_E d_a,\;
  \exp\!\left(\theta_t [R_E r_a]_{\times}\right) Q_t
\right)
$$

$\mathbf{x}_t$와 $Q_t$는 end-effector의 현재 위치·자세이고, $d_a$·$r_a$는 액션이 지정한 이동/회전 방향(회전이면 $d_a=0$, 이동이면 $r_a=0$)입니다. $\sigma_t$, $\theta_t$는 미리 보정해둔 이동/회전 크기, $R_E$는 의미상의 방향을 해당 embodiment의 실제 좌표계로 옮기는 변환, $\Pi_E$는 작업공간·관절 한계를 지키도록 잘라내는 투영입니다.

이 식의 의미는 명확합니다 — "어느 쪽으로 얼마나 움직일지"에 대한 의미적 결정(VLM의 몫)과 "그게 이 로봇에서 정확히 몇 cm, 몇 도인지"에 대한 물리적 변환(인터프리터의 몫)을 완전히 분리했다는 겁니다. 새 로봇을 지원하려면 $g_E$ 하나만 새로 짜면 되고, VLM이 보는 액션 어휘는 손댈 필요가 없습니다. 뒤에서 볼 파인그레인 제어 실험(스텝 크기만 2cm→1cm로 바꿔서 성능이 오르는)이 이 분리 설계의 실질적 이득을 보여줍니다.

같은 인터페이스는 두 모드로 쓰입니다. Zero-shot 모드는 프론티어 VLM(Gemini-3.1 Pro 등)을 그대로 컨트롤러로 씁니다. 파인튜닝 모드는 Qwen3.5-2B 같은 소형 오픈소스 모델에 LoRA를 붙여 다음 목적함수로 학습시킵니다.

$$
\mathcal{L}(\theta) = -\!\!\sum_{(\ell,\, o,\, h,\, a)\, \in\, \mathcal{D}}\!\! \log \pi_\theta\!\left(a \mid \Phi_{\mathcal{P}_{\mathrm{min}}}(\ell,\, o,\, h)\right)
$$

시연 데이터셋 $\mathcal{D}$에서 뽑은 (지시, 관측, 이력, 정답 액션) 튜플에 대해, 최소한의 맥락 $\Phi_{\mathcal{P}_{\mathrm{min}}}$만 주고 정답 의미 액션 토큰의 로그우도를 최대화하는 표준적인 크로스엔트로피입니다. 여기서 중요한 포인트는 액션이 별도의 액션 헤드나 특수 토큰 없이 VLM의 원래 어휘(`MV_FWD` 같은 텍스트 토큰) 그대로 예측된다는 점입니다. 액션이 "새로 배워야 할 낯선 출력 형식"이 아니라 모델이 원래 하던 다음 토큰 예측의 연장선이라서, 파라미터의 약 3%만 건드리는 LoRA로도 학습이 된다는 논리입니다.

이 harness는 Perception·Reasoning·Action 세 단계에 아래 플러그인들을 얹어 동작합니다.

| 단계 | 플러그인 | 기능 |
|---|---|---|
| **Perception** | | |
| | Multi-View Guidance | 카메라 뷰마다 역할과 우선순위를 VLM에게 알려줌 |
| | Proprioception | 로봇 상태·접촉·그리퍼 상태를 텍스트 피드백으로 변환 |
| **Reasoning** | | |
| | Subtask Planning | 시각적으로 확인 가능한 완료 기준을 가진 서브태스크 계획을 유지 |
| | Situated Planning | 불확실한 결정을 미뤄뒀다가 필요한 정보가 보이면 그때 재계획 |
| | Action Chunking | 정밀 피드백이 필요 없을 때 액션을 묶어 open-loop로 실행 |
| | Adaptive Step | 목표까지 거리에 따라 스텝 크기를 크게/작게 조절 |

의미 액션 공간이 이산적이고 사람도 조작 가능하다는 점을 이용해, 저자들은 GUMI(GUI Manipulation Interface)도 함께 만들었습니다.

이 그림에서 흥미로운 부분은 오른쪽 패널입니다. 사람이 키보드로 버튼을 눌러 시연을 모을 수도 있지만, 컴퓨터 사용(computer-use) 에이전트가 브라우저 화면을 보고 똑같은 버튼을 클릭해서 시연을 대신 수집할 수도 있다는 걸 실제로 보여줍니다. 스크린샷 속 에이전트가 마침 Claude로 표시돼 있는데, 이건 아마 예시로 캡처한 것이겠지만, "이 액션 공간은 사람의 키보드든 VLM의 클릭이든 컴퓨터-사용 인터페이스 층위에서 완전히 동일하게 다뤄진다"는 저자들의 핵심 주장을 그대로 시각화해주는 장면이라 인상 깊었습니다. 같은 시연을 한 번 모으면 의미 액션 정책과 연속 제어 정책(저수준 궤적) 양쪽을 학습하는 데 재사용할 수 있고, 물리적으로 로봇 옆에 있지 않아도 원격으로 데이터를 모을 수 있다는 것도 실용적인 이점입니다.

플러그인 하나씩 껐을 때 성능이 어떻게 바뀌는지도 체계적으로 보여줍니다.

전체적으로 대부분의 플러그인이 96%(기본 설정)에서 시작해 껐을 때 60~76%대로 떨어집니다. 특히 흥미로운 건 (vi) Visual Prompt와 (vii) Situated Planning인데, 이 둘은 "일반 Plate 태스크"에서는 켜나 끄나 차이가 거의 없습니다(96 vs 94, 96 vs 96). 하지만 각자를 위해 설계된 전용 시나리오 — 손잡이를 잡아야 하는 컵, 뒤집힌 컵 밑에 숨겨진 물체 찾기 — 에서는 40%→85%, 35%→85%로 극적으로 갈립니다. 즉 이 두 플러그인은 "항상 켜두면 좋은 것"이 아니라 "필요한 상황에서만 켜는 게 맞는" 조건부 설계라는 걸 저자들도 인지하고 있고(기본값 off), 데이터가 그 설계를 뒷받침합니다. (iv) Action Chunking도 패턴이 재밌는데, 아예 끄면 성공률은 96%로 유지되면서 모델 호출만 32번으로 늘고, 반대로 항상 켜두면 호출은 20번으로 줄지만 성공률이 74%로 떨어집니다 — "선택적으로만 묶어라"는 절충이 정확히 데이터로 뒷받침되는 사례입니다.

액션 공간을 어떻게 표현하는지에 대한 통제 실험도 짚을 만합니다.

![액션 표현 방식별 성능 비교와, 이름 없이 기호만 줬을 때 모델이 추론한 방향 매핑표](/assets/img/posts/2609.10522/fig9_action_repr.png)
_Figure 9. (a) 의미 이름+컨벤션(기본, 100%) / 이름만(90%) / 임의 기호+컨벤션(95%) / 임의 기호만(5%). (b) 기호만 줬을 때(D) 20개 에피소드에서 모델이 추론한 "실제 방향 vs 모델이 추측한 방향" 혼동 행렬_

(a)에서 가장 눈에 띄는 대비는 "임의 기호(A, B, C...)를 써도 명시적 컨벤션(글로 설명된 의미)만 있으면 95%로 기본값에 근접한다"는 점입니다. 반대로 "의미 있는 이름(MV_LEFT 등)만 주고 컨벤션 설명을 빼면" 90%로 오히려 조금 더 떨어집니다. 즉 이름 자체보다 "이 기호가 정확히 무엇을 뜻하는지 설명해주는 텍스트"가 grounding의 핵심이라는 뜻이고, 의미 있는 이름은 그 설명이 없을 때를 대비한 보조적인 사전 지식 정도라는 겁니다. (b)의 혼동 행렬은 더 흥미로운데, 설명 없이 기호만 주고 스스로 관측 변화로 방향을 추론하게 하면(설정 D) 정답률이 23.3%(우연 수준 16.7%보다 살짝 높은 정도)에 그치고, 특히 Left↔Right가 서로 뒤바뀌어 추론되는 "거울상 오류"가 두드러집니다(왼쪽으로 움직였는데 오른쪽이라고 추론). 이건 시각적으로 좌우가 대칭적인 장면에서 방향을 순수하게 관측만으로 귀납하기가 얼마나 모호한지 보여주는 사례라, 개인적으로 이 논문에서 가장 재밌게 읽은 실험 중 하나였습니다.

이 외에도 파인튜닝 백본 크기 실험에서는 2B급이 정밀도와 반응성의 균형점이었고(1B급은 국지적 미세조정을 과도하게 반복해 스텝 수가 늘어나는 반면, 9B급은 정밀 태스크에서만 이득), 테니스공처럼 빠른 교정이 정밀도보다 중요한 태스크에서는 오히려 작은 모델이 더 나은 경우도 있었다고 합니다.

## 아쉬운 점 / 의문점

- **평가 규모가 크지 않습니다.** 실제 로봇 실험은 embodiment 2종, 물체 5종, 목적지 2종의 조합이 중심입니다. 일반화 주장을 뒷받침하는 축(태스크·환경·embodiment)은 다양하지만, 각 축 안에서의 절대적인 태스크 개수 자체는 많지 않아서 "정말 광범위한 조작 능력"이라 부르기엔 조심스러운 면이 있습니다.
- **파인튜닝이 zero-shot보다 못한 경우가 여럿 있습니다.** Cross-Task 평균은 ZS 89% vs FT 86%, Cross-Environment는 100% vs 88%로 ZS가 계속 앞섭니다. 논문은 "두 모드 모두 baseline을 이긴다"는 데 집중하지만, FT가 ZS 대비 구조적으로 왜 뒤처지는지(데이터 양의 한계인지, 2B 모델의 근본적 한계인지)에 대한 논의는 깊지 않습니다.
- **인터프리터의 스텝 크기·안전 한계가 사람이 직접 보정한 값입니다.** 2cm/4cm 같은 수치, 회전 15도 단위 등은 논문에 "calibrated"라고만 나와 있고 구체적으로 어떻게 정했는지는 명시되어 있지 않습니다. 새 embodiment마다 이 보정 작업이 얼마나 손이 가는 일인지 궁금한데, 본문만으로는 알기 어렵습니다.
- **Zero-shot 모드는 결국 폐쇄형 프론티어 모델과 API 지연시간에 의존합니다.** Fig. 1의 속도 비교를 보면 zero-shot 모드는 스텝당 8~20초가 걸리는 반면 파인튜닝 모델은 12~33Hz로 훨씬 빠릅니다. "VLM 하나로 로봇을 조작한다"는 프레이밍은 매력적이지만, 실시간성이 필요한 태스크에서는 이 지연이 실질적인 제약일 것 같습니다.
- **정성적 데모(옷 개기, 케이크 자르기, 지우개로 글씨 지우기 등)는 평가표에 없습니다.** Figure 1에 보이는 흥미로운 시연들이 정량 평가 테이블에는 포함되지 않아서, 이런 태스크들의 실제 성공률이 얼마나 되는지는 논문에 명시되어 있지 않습니다.

## 마치며

이 논문에서 제일 마음에 든 지점은 "VLA처럼 회귀할지, 프로그램처럼 위임할지"라는 이분법 자체를 문제 삼았다는 점입니다. 의미 결정과 물리 실행을 완전히 분리해두면 — 즉 모델은 "왼쪽으로 한 칸"만 결정하고 "정확히 몇 cm인지"는 인터프리터가 담당하면 — 새 정밀도, 새 embodiment, 심지어 액션 표현 자체를 바꾸는 실험까지 전부 인터프리터 쪽만 건드려서 해결된다는 걸 Fine-grained control이나 Rotation extrapolation 같은 분석 섹션들이 설득력 있게 보여줍니다. 개인적으로는 GUMI가 Claude 같은 컴퓨터 사용 에이전트로 시연을 자동 수집하는 그림이 특히 인상적이었는데, 로봇 시연 수집이라는 전통적으로 사람 손이 많이 가던 작업이 "웹 브라우저를 조작하는 에이전트"라는 완전히 다른 영역의 기술로 자동화될 수 있다는 걸 보여주는 사례라고 생각합니다. 다음에 관심 가는 건, 이 액션 공간이 병렬 그리퍼를 넘어 다지 손이나 휴머노이드처럼 자유도가 훨씬 높은 embodiment에서도 "이산적이면서 의미 있는" 형태로 자연스럽게 확장될 수 있을지입니다.
